# PC 版现代化验收矩阵

配套文档：[pc-modernization.md](pc-modernization.md)（需求）、[runtime.md](runtime.md)（架构与诊断）、[first-level.md](first-level.md)（序章手验键位）。

本文把主文档的验收顺序拆成可逐条结案的条目。它只定义「怎么判定完成」和「哪些话还不能说」，不改需求、不改源码、不要求立即执行测试。

需求优先级：主文档 > 本文。本文与主文档冲突时，以主文档为准并回改本文。

> 待整合：主文档「验收顺序」一节尚未链接本文，由文档维护者在合并时补链接；本文不修改主文档。

## 1. 证据等级

| 等级 | 名称 | 定义 | 可否单独结案 |
| --- | --- | --- | --- |
| **S** | 静态推断 | 仅来自反编译符号表（`build/*.tsv`）或宿主源码阅读，未经运行确认。含「同名函数的重复实现」「无法命名类」等已登记阻塞项。 | 否 |
| **A** | 自动验证 | 由脚本/构建产物在本地无人值守重复执行，判定条件可写成断言（像素哈希、退出码、日志正则、文件字节）。 | 是（仅覆盖被断言的范围） |
| **P** | 私有回放 | 需原版 `Lament-Island.zip` 与本地安装盘副本，按已记录路线重放并留存日志/截图。第三方无资产时不可复现。 | 是（需同时留档路线与提交号） |
| **U** | 用户手验 | 人在键盘/鼠标前的主观判断（观感、可读性、操作性）。 | 是（须记录判定人与判据） |
| **M** | 缺失 | 无反编译符号、无实现、无测试。等价于「未验证」。 | 否 |

结案门槛：

- 任一条目结案 = 至少一条 **A**，或 **P** 加 **U**。
- **S** 只能支撑设计取舍与风险登记，不能作为通过依据；**S 亦不能证明功能不存在**，只能证明「已识别的符号里没有」。
- 一条目所用的每一项证据都要能追溯到「提交号 + 构建目录 + 资产来源」，否则降级为 **M**。

## 2. 通用前置条件（适用于所有条目）

1. 从桌面终端启动，窗口获得焦点；**不加 `--first-frame`**——`runtime.md` 已说明它只是首帧探针，不是游玩模式。
2. 使用**独立安装盘副本**（`mktemp -d build/...`）：「新的开始」会重置临时存档，共用目录会污染后续存档条目。
3. 每次记录必须写清：提交号、构建目录、是否用原版 ZIP、窗口尺寸、雾/AA/过滤设置、按过的键序列、`runtime.log` 路径。
4. 记录依据是 `guest frame` 行给出的实际绘制/呈现位置与像素哈希；黑窗口图像不算首帧。
5. 报错优先取**首次出现**的未支持指令地址、DLL/ordinal 或 `unhandled Symbian leave`；后续症状不作根因。外部 `timeout` 的退出码 `124` 是限时结束，不是宿主报错。
6. 已知噪声：`texture\scene\` 贴图缺失警告目前存在。它是**必须显式列出**的既有缺陷，不得在报告里省略，也不得用 `texture\sd2\` 同名文件自动回退掩盖（`runtime.md` 明确禁止该回退）。
7. 判定「同一输入」目前没有输入录制/重放工具：`pump_window_input` 每个调度轮只投递一个 SDL 事件，无法回放按键序列。因此基线对比只能靠「人按同一路径 + 帧哈希」，属 P/U 混合；纯 A 级的像素对比需先补输入脚本重放（见 §6 推荐项）。

## 4. 逐项验收

每条格式：**需求** / **前置条件** / **观察点** / **通过判据** / **失败证据** / **不应宣称** / **当前等级**。

### 4.1 R1 软件渲染基线

- **需求**：现代后端先复现 CPU 渲染器可观察行为，再逐项启用增强；不能凭「画面大致相似」替换遮挡、透明与合成规则。
- **静态事实**（S）：`DrawSceneGeometry` 清目标、设相机、投影 `0x58` 字节三角记录，按 `+0x48` 分派：`0`=`RasterizeTexturedTriangleOpaque`（写颜色+深度），`4`=`RasterizeTexturedTriangleType4`（颜色+深度），`5`=`Type5`（双贴图索引），`6`=`RasterizeTexturedTriangleAlphaMask`（逐像素写 `renderer+0x40` alpha 缓冲），其余走 `RasterizeShadedTriangle`（无贴图采样）。`InitRendererBuffers` 分配 color/depth/alpha 三缓冲与 70000 项倒数表；`SortDepthPairs` 在分派前对深度键排序；`CompositeLightingBuffer` 按 alpha 缓冲字节权重做逐像素 RGB565 混合并带深度测试。
- **前置**：原后端构建产物；同一场景、同一相机（`SetRendererCameraPosition` + `SetRendererViewOffset` + `SetProjection` 同值）、同一时间步。
- **观察点**：输出 RGB565 帧哈希；几何覆盖率；遮挡顺序；alpha 缓冲非零像素集；光照合成后像素。
- **通过判据**：同输入下可见像素一致（或差异集可逐一解释为已知缺口）；透明度掩码像素集合一致；HUD 像素一致。
- **失败证据**：首个差异像素坐标 + 该三角的 `+0x48` 类型 + 是否落在 alpha 缓冲；若是贴图问题，附 `texture\scene\` 缺失警告原文。
- **不应宣称**：不得把「同场景看起来一样」当通过；不得宣称深度值逐位相等（新后端精度不同时只断言顺序与覆盖率，并写明放宽理由）；不得由序章基线推断第一章。
- **当前等级**：S 完整 + A 部分（哈希机制可用，逐像素对比工装未建）。

### 4.2 R2 现代 3D 接管完整管线

- **需求**：顶点变换、裁剪、光栅化、深度测试全部在现代 GPU 管线内完成，CPU 光栅结果只作对照；BSP 继续服务地图组织/碰撞/空间查询，但不是渲染器限制。
- **前置**：新后端可整体停用 CPU 光栅路径而不改变场景提交集合；可统计每帧三角形提交数与被裁剪数。
- **观察点**：停用 CPU 光栅后场景是否完整；遮挡是否正确（近物压远物）；`Type5` 双贴图与 alpha mask 是否各有独立处理；是否有 CPU 回读整帧。
- **通过判据**：同输入帧的可见三角形集合与绘制顺序与基线一致；深度关系无反转；透明边缘无 `0xF81F` 透色键泄漏或黑边；整帧无 CPU 逐像素回读。
- **失败证据**：具体表现为「远处墙面盖住近处角色」= 深度测试反向；「镂空贴图边缘出现彩色/黑色描边」= 透明键被当作混合而非 alpha-test；附截图与对应材质名。
- **不应宣称**：不得宣称具体 API（Vulkan/D3D12/Metal）未定案前已选定；不得宣称 BSP 已从渲染路径移除（仅移除其渲染限制）。
- **当前等级**：S（只有原管线证据，新后端不存在）。

### 4.3 R3 宽屏与非 4:3 窗口

- **需求**：支持宽屏；过场按素材比例显示（必要时黑边）；可玩场景保持原镜头语义；HUD/对白/菜单按安全区锚定。
- **现状静态事实**（S）：宿主 `window_gc.h` 固定 `window_width=176`、`window_height=208`，创建 `176*3 × 208*3` 窗口，用 `SDL_RenderCopy(..., NULL, NULL)` 把整张 RGB565 纹理拉满窗口，未设逻辑尺寸或宽高比提示。原容器构造还把 `160x208` 修正为 `176x208`（`CIsLandContainer::ConstructL`），视频目录在 `Video\176x208` 与 `240x320` 之间选择（`CreateScreenBuffers`）。
- **［推断］**：原画幅 176:208 ≈ 0.846，比 4:3 更窄；PC 宽屏必然引入「横向附加区域」或「左右留边」的选择，而主文档要求保持镜头语义，因此首选附加区域 + 安全区锚定。是否分离横/纵投影比例未验证（`SetProjection` 只见 `Math::ATan` 取角与 `+0xc..+0x60` 的 scale/offset 表）。
- **前置**：可枚举窗口尺寸（176×208、320×240、640×480、1280×960、1280×720、2560×1080、3440×1440）；过场与可玩场景分别测。
- **观察点**：影片画面宽高比；黑边是否对称；可玩场景在原画幅内的物体屏幕位置是否与基线一致；扩展区是否出现未制作几何/空洞；HUD、对白框、菜单距边距离。
- **通过判据**：影片宽高比误差 < 0.5% 且不裁切内容；同场景同镜头下，原画幅内物体位置与基线一致（同渲染后端内自比）；HUD 与对白框不触边、不被裁；扩展区不暴露无贴图空洞。
- **失败证据**：影片被拉伸（量出像素宽高比）；HUD/对白被裁或贴边；扩展区出现明显空腔并被当作新场景；鼠标点选位置与实际命中不一致（与 I5 联动）。
- **不应宣称**：不得在只测 16:9 时宣称「支持宽屏」；不得宣称「扩大 FOV」通过（那是改镜头语义，主文档禁止）；不得用序章证明章节过场；不得由 1280×960 推断超宽屏。
- **当前等级**：S。据此可判定的只有：**当前宿主是固定 528×624 的整数 3 倍等比窗口，不支持宽屏**（未设可缩放标志，也无法选画幅）。若把窗口改成可缩放或按显示器创建，`SDL_RenderCopy(..., NULL, NULL)` 的整纹理拉满会立刻变成非等比拉伸——这条是机制推断 ［推断］，不是已观测现象。

### 4.4 R4 抗锯齿

- **需求**：支持现代硬件 AA；具体方案由后端验证决定；不对整帧不可控模糊；文字/HUD/镂空边缘必须可读稳定。
- **前置**：后端可切换 AA 开关与方案；可输出 1:1 与放大截图；可连续取多帧（判断时间稳定性）。
- **观察点**：石阶/栏杆/梁等长斜边锯齿；镂空贴图边缘；文字与 HUD 笔画锐度；静止镜头多帧差分；运动镜头残影。
- **通过判据**：斜边锯齿可见下降（建议记录边缘像素对比度统计或 4× 放大目检对比）；HUD/文字笔画宽度与基线一致（不糊、不增粗）；静止时连续帧差分为 0（无 TAA 抖动）；运动时无可见残影。
- **失败证据**：HUD 被后处理导致发虚（对照截图 + 文字区域像素差）；透明键边缘出现黑边/彩边（应为 alpha-test）；静止画面闪烁（帧差分非零）。
- **不应宣称**：不得宣称「支持 MSAA」若实际只做了后处理 AA；不得用单张静止截图宣称时间稳定性；不得宣称 AA 不影响性能。
- **当前等级**：M。

### 4.5 R5 纹理过滤

- **需求**：保留原贴图尺寸与内容、低模几何；允许 mipmap/各向异性/柔和采样；不增面数、不重绘。
- **静态事实**（S）：`DecodeSbmBitmap` 把 4 字节 BGR 调色板转 RGB565 并翻转行；渐变色位图走 `BlitIndexedBitmapScaled`（透色索引 `0xF81F`），这些是「原贴图内容」的定义。
- **前置**：可控采样设置；取斜视地面、栅栏、远景墙面各一处。
- **观察点**：贴图内容/尺寸是否变化；斜视高光闪烁（mipmap 缺失）；远景是否糊到丢细节；透色键边缘。
- **通过判据**：贴图内容与尺寸与基线逐字节/逐像素一致；斜视无高频闪烁；透色区域无灰边/黑边。
- **失败证据**：出现新生成的 mip 层被当作「新资产」交付；透色键被双线性过滤产生彩边；贴图尺寸被改（对比 SBM 宽度字段 `+0x10`/`+0x14`）。
- **不应宣称**：不得宣称「提升贴图质量」或「高清化」；不得宣称「无闪烁」仅凭静止截图。
- **当前等级**：S（SDL 纹理默认缩放质量为最近邻属库默认行为 ［推断］，未在本仓库实测）。

### 4.6 R6 三档雾

- **需求**：原版风味 / 更沉浸 / 关闭；只改渲染，不改地图边界、碰撞、AI、脚本、交互距离；远景暴露未制作区域时用边界/天空层/保守裁剪处理。
- **证据状态**：**符号表中没有任何雾相关符号**（`fog`/`haze`/`attenuate` 全表零命中）。因此：
  - 「原版存在距离雾」**未验证**，不能作为既定事实写进验收结论。
  - 「原版风味」档缺少可对照的原始实现，必须先补静态定位（是逐顶点衰减、逐像素 `CompositeLightingBuffer` 权重，还是根本没有），否则该档不可验收。
- **前置**：（1）先完成原距离衰减路径的静态定位并写入 `build/` 证据；（2）三档可运行时切换且不改任何模拟状态。
- **观察点**：雾颜色、起始距离、衰减曲线；切换档位前后的同帧画面差；同位置碰撞结果；物品拾取与互动的触发距离；远景空洞。
- **通过判据**：原版档与基线在阈值内一致（阈值需在补完对照实现后确定）；关闭档仅去掉距离雾而保留其他光照材质；三档切换下 `TestMoveBlocked`/`HandlePlayerInteraction`（`0.7f`/`0.3f` 阈值）判定完全一致。
- **失败证据**：切雾后拾取提示变化或可拾取距离变化（脚本/交互被污染）；关闭雾后暴露未制作区域且未做边界处理；`原版风味` 档无可对照实现却声称「一致」。
- **不应宣称**：不得宣称原游戏「有雾效」；不得宣称关闭雾=关闭全部光照衰减；不得宣称三档已验收在对照实现缺失时。
- **当前等级**：M（实现与基准均缺）。

### 4.7 R7 HUD、对白与 2D 层

- **静态事实**（S）：文字直接画进 176×208 帧缓冲（`DrawTextString`/`DrawWideString`/`DrawWideGlyph`，字形 `0x12` 字节、按字符类选字体表）；对白框 `DialogueBoxRender` 填 `(0,0,0xb0,0x3c)` 即整宽 176×60；教程按键 HUD 由 `DrawKeyGlyph` 把 `w,s,a,d,o,/,*` 与数字映射到键位图。
- **风险（重要）**：教程键位图是**手机键位**语义。PC 改用方向键 + `Q/E/F/Tab` 后，键位图会与实物不符。这是一项独立缺陷，不能靠「HUD 渲染正常」掩盖。
- **前置**：每档画幅分别截图（原生、整数倍、非整数缩放、超宽）；中文文本至少取对白一段、菜单一项、物品名一项。
- **观察点**：文字是否乱码/方框；断行与裁剪；对白框与 HP 栏安全区；菜单选中态；教程键位图与 PC 实际键位是否一致。
- **通过判据**：无方框字（Fontconfig 有可用简体中文字体）；对白框在 176 宽归一化后的相对位置与基线一致；非整数缩放下文字笔画不断裂；键位图与实际键位一致或明确标注映射。
- **失败证据**：方框/乱码（附字体匹配失败日志）；HUD 触边被裁；键位图显示 `w/a/s/d` 而接受方向键且无说明。
- **不应宣称**：不得宣称「HUD 已重制」或「键位提示已更新」，除非确有改动并单独验收。
- **当前等级**：S + A（序章绘制已自动覆盖）+ P。

### 4.8 R8 影片

- **静态事实**（S）：`CreateScreenBuffers` 选择 `Video\176x208` 或 `Video\240x320`；章节转场打开 `VIDEO/176X208/0.SVO`（`runtime.md`）；AVI 路径存在 `avi_reader_*`、`yuv420_to_rgb565_blit`、`video_blit_rgb24_rotated`（`param_9` 选 0/90/180/270 扫描顺序）。
- **前置**：序章开局影片与第一章影片分别记；记录分辨率与时长。
- **观察点**：画面比例与黑边；旋转方向；音画同步；结束后的状态推进（第一章须落到 `li2.bsp.fix` + `SCRIPT/2`）。
- **通过判据**：等比、无裁切；旋转正确；音画偏移在可接受范围内（建议 < 100ms，需先定阈值）；播放结束后进入下一状态而非停留/黑屏。
- **失败证据**：画面拉伸或镜像；播放完停在同一状态；音画明显错位；只播音频无画面。
- **不应宣称**：不得用序章开局影片代替章节影片；不得宣称「所有视频可用」——只见到 176×208 与 240×320 两条路径。
- **当前等级**：S + P。

### 4.9 I1–I3 `Q` / `E` / `F`

- **需求**：`Q` 装镐子、`E` 装弹弓，未获得时不给出错误使用结果、不强制切到别的东西；`F` 只选中剧情明确需要之物、不自动使用、多候选时不替玩家揭示答案。
- **现状静态事实**（S，源码级）：宿主 `pump_window_input` 只映射 `Return/KP_ENTER→0xa4`、`Esc→0xa5`、`RSHIFT→0xa7`、方向键 `0x0e..0x11`、小键盘数字、`PageUp→0x7f`、`PageDown→0x85`，**没有 Q/E/F/Tab，也没有任何鼠标事件分支**。所以「已实现」不可宣称。
- **前置**：新键位接入后，准备两个状态：未持有、已持有；各记录一次。
- **观察点**：物品列表当前选中索引；是否触发使用动作；是否弹对话/音效；`F` 是否自动使用；多候选时是否突显某个。
- **通过判据**：未持有时选中项不变或明确无操作，无错误对话、无使用结果；持有时仅选中、需再显式使用才生效；`F` 从不自动使用；多候选时 UI 不标记「正确答案」。
- **失败证据**：未获得时出现「不能使用」类失败对白（越界语义）；`F` 直接触发脚本结果；`E` 在无弹弓时静默换成其他物品。
- **不应宣称**：不得在只有 S 证据时宣称「Q/E/F 可用」；不得宣称「键位与教程一致」。
- **当前等级**：S（未实现）。

### 4.10 I4 `Tab` 背包

- **需求**：开关背包；打开时暂停世界更新，输入不传给场景。
- **观察点**：打开期间角色位置/动画帧/计时是否冻结；方向键是否仍移动角色；场景状态字节是否变化；关闭后是否有残留输入导致的误动作。
- **通过判据**：打开期间角色位置与动画帧不变；输入对象字段（`ResetInputState` 清零的 `+0x58..+0xa4`）不被新的输入置位；场景状态不变；关闭后无「延迟触发」。
- **失败证据**：背包内按方向键角色移动；关闭瞬间角色走一步（输入泄漏）；世界计时在背包内推进。
- **不应宣称**：不得宣称「暂停 = 全局线程停止」——音频、影片、非世界 UI 的暂停语义必须按原状态机逐项定义（已识别状态包括 `0x16` 地图、`0x17` 暂停菜单、`5/6` 对白、`7` 物品图、`8` 章节事件、`0x19` 物品图选择、`0x24` 消息面板、`0x27` 空转），未定义前不得概括。
- **当前等级**：S（未实现）。

### 4.11 I5 鼠标使用物品

- **静态事实**（S）：符号中有 `LoadMouseScript` 读取 `script\mouse` 并加载光标模型（`mouse/name` 记录），说明原系统有**光标模型**；但已分析模块中**没有指针/触摸事件路径**（`TPointer`/stylus 零命中）。所以「原游戏支持鼠标」不能宣称，鼠标层是新加输入层。
- **前置**：可点选背包与场景；准备「直接可用」与「需目标」两类物品。
- **观察点**：点击后走的是原使用路径还是新捷径；需目标物品是否回到场景选目标；选目标是否受脚本 `HasResult/NoResult` 约束；命中测试与画面是否一致。
- **通过判据**：成功/失败/取消均落到原脚本分支，物品消耗与存档更新走原代码；目标选择不改变碰撞与交互距离；点选位置与画面元素对齐（含非整数缩放下）。
- **失败证据**：点击绕过 `HasResult` 直接给结果；需目标物品被立即使用；点选偏移导致选错物体。
- **不应宣称**：不得宣称「原版鼠标操作已保留」；不得宣称「背包 UI 已完整支持鼠标」直到拖拽（I6）也通过。
- **当前等级**：S（未实现；无指针事件符号）。

### 4.12 I6 拖拽合成

- **静态事实**（S）：`LoadCombineScript` 解析 `type/gfail/ginfo/item1..item5/success/info/icon` 的配方记录，由 `ProcessItemScript` 调用；物品记录 `0x4b8` 字节，列表在 `engine+0x530`，`HasSceneItem` 按 id 查三条列表。
- **前置**：至少一条成功配方与一条失败配方（可用同一物品自合失败）。
- **观察点**：拖 `A→B` 后是否调用配方表；成功时的消耗与结果；失败时是否消耗、是否触发单击使用、UI 是否回原位；结果是否写进 `.itm`。
- **通过判据**：成功路径由 `item1..5` 匹配决定；失败路径零消耗、零使用、位置复原；存档文件字段格式不变。
- **失败证据**：失败消耗物品；释放瞬间触发单击使用（「拖拽被当成点击」）；合成结果绕过脚本写入新字段。
- **不应宣称**：不得宣称「支持全部配方」除非穷举 `combine` 脚本；不得宣称合成与存档兼容（要按 C3 校验）。
- **当前等级**：S（规则表存在，交互层未实现）。

## 5. 跨条目不变式

以下断言对每个渲染/输入条目都成立，任一被破坏即该条目不通过：

| 不变式 | 可观察证据 |
| --- | --- |
| 玩法与脚本结果不变 | 同一位置/朝向下 `HandlePlayerInteraction` 结果、对白文本、`HasResult/NoResult` 分支一致 |
| 碰撞与移动不变 | 同一位置与方向下 `TestMoveBlocked`/`TraverseBspTree` 结果一致 |
| 交互距离不变 | `0.7f`/`0.3f` 阈值语义不变（拾取提示出现距离一致） |
| 资产内容不变 | SBM 解出的宽高与调色板/像素一致；无新增多边形 |
| 存档格式不变 | 文件集合、字段宽度、`tmp.id` 校验一致 |
| 章节与镜头语义不变 | `li%d.bsp.fix`、`SCRIPT/%d`、相机位置/偏移/投影输入值一致 |

注意：不变式允许「新后端内部实现不同」，只约束**可观察结果**。若某条只能通过放宽阈值成立，必须在报告中写明放宽理由与实测差异。
