# PC 输入与背包设计

本文是 [PC 版现代化需求](pc-modernization.md) 的子系统设计说明，只覆盖输入上下文、暂停语义、装备选择、物品使用、拖拽合成、原脚本/存档调用边界、键位配置和可访问性。

本文不改玩法：物品集合、使用条件、合成配方、成功/失败结果、剧情分支和存档格式仍由原游戏代码决定。**本文不设计相机或麦克风替代玩法**，也不把输入改造当作绕过原判定的手段。

证据标记：

- **【已确定】**：`docs/pc-modernization.md` 的需求，或原二进制中已定位、可在 `build/*.tsv` 复核的代码事实。
- **【推荐】**：本文给出的实现方案，尚未实现，需按第 9 节验收。
- **【未验证】**：当前证据不足以断言，实现前必须先补证据；不得按推断落地。

## 1. 证据基础

| 事实 | 证据 |
| --- | --- |
| 宿主把按键事件交给容器，容器原样转给引擎的按键动作分发 | `CIsLandContainer::DispatchKeyEvent`（0x587b8）：`forwards CEngine::DispatchKeyAction(0x59e90) and returns 1 (event consumed)` |
| 按键分发是"键码 → 动作标志"的 switch，按下与清除是两条路径 | `CEngine::DispatchKeyAction`（0x59e90）：`switch on key code (1,0xe..0x11,0x30..0x39,0x7f,0x85,0xa2..0xa7,0xe3..0xe5) sets action flags +0x10..+0x100 and movement bits; also clears via second switch (param_3==2/3)` |
| 还有按帧读取按键状态、带重复计时的入口 | `ProcessKeyInput`（0x6b62c）：`reads key state buffer and sets input flags +0x202c..+0x2031 (fire/forward/back/strafe) with repeat timers +0x1e4c/+0x1e54` |
| 输入状态对象挂在 `engine+0x18`，可整体清零 | `ResetInputState`（0x3ff9c）：`zeroes input fields +0x58..+0xa4 and +4..+0x34 of the engine+0x18 input object` |
| 存在第二个几乎相同的输入复位，语义未定 | `0x3feac`（blockers）：`Two near-identical input resets exist; which UI layer each belongs to is unresolved` |
| 场景按状态机分发，UI 各自是一个状态，不在场景状态里"叠加" | `GameStateDispatch`/`GameStateRender` 的多条记录：state 1（物品模型查看）、5（对白）、6（场景对白）、7（物品 sd2 图）、8（章节事件）、0x10（清除物品记录）、0x11（记录场景坐标）、0x16（地图）、0x17（暂停菜单）、0x19（物品图片选择）、0x24（信息面板）、0x27（弹图） |
| 暂停菜单就是状态 0x17，五行，选中项 0..4 | `PauseMenuTick`（0x1afec）、`PauseMenuRender`（0x1ab88）：`draws 5 rows (loop 0..4, rect 0x33x0x10, step 0x14)`，`option 1 sets state 0x13, option 2 ... loadsave\%d.dat, options 3/4 set state 0x15 and scene+0x214` |
| 关闭 UI 是通过写场景状态完成的，不是隐藏图层 | `CloseMapScreen`（0x1adfc）：`clears flag ... writes scene state 10 with substate 1` |
| 原游戏自带键位配置界面，持久化到 `key` 文件 | `KeyConfigScreenTick`（0x1bee8）`scene mode 7`；`ReadKeyConfigFile`（0x2059c）/`WriteKeyConfigFile`（0x202f8），`opens 'key' with share 0x200` |
| 原版教程 HUD 已经用字符键位图像 | `DrawKeyGlyph`（0x2a758）：`Switch maps 'w','s','a','d','o','/','*' and digits to key-image glyphs` |
| 物品记录定长 0x4b8，含 id、图片/模型索引、变体数、变体选中字节 | `LoadItemInfoScript`（0x23ddc）、`LoadItemTableScript`（0x241a8，解析 `picpos`/`tab`）、`ItemPictureSelectTick`（0x33748，`cycles item variant engine+0x224 bounded by record+0x484 and swaps selection bytes +0x74+i`） |
| 物品集合是三组动态数组，可按 id 查询、追加、删除、交换 | `GrowItemRecordArray`（0x2b580，头部 `{0x4b8,count,capacity}`）、`AppendItemRecord`（0x2b6e4）、`SwapItemRecords`（0x2b7c0）、`RemoveItemRecordById`（0x2bb50）、`HasSceneItem`（0x3a500，`scans the three item lists at engine+0x530 (counts at +4)`） |
| 合成是脚本数据表，最多 5 个来源物品 | `LoadCombineScript`（0x23758）：`type/gfail/ginfo/item1..item5/success/info/icon` |
| 原版合成界面有双光标与成功/失败图标、合成框资源 | `LoadItemSelectSprites`（0x13e8c）：`ui\itemsel/itemfont/itemcursor/iconsuc/iconfail/combcurr/combcurw/combframe`；`LoadBookSprites`（0x140e4）：`bookcursor`, `itemcombine` 等 |
| 使用物品会进入多种脚本 UI，不是单一函数调用 | `ProcessItemScript`（0x2bde0）驱动物品交互状态；`InitMotorPuzzleUI`（0x1c594）对 id `0xb/0x16/0xc` 载入电机小游戏（`InitMotorPuzzleUI` 由 `ProcessItemScript` 调用） |
| 物品信息分页直接读输入对象字段 | `ItemInfoPageTick`（0x2cb6c）：`item info paging with index +0x534, line +0x54c and input +0x58/+0x5c/+0x60` |
| 存档只通过原写盘函数落地，字段固定 | `WriteSaveIdFile`（0x1f628，`count engine+0x528`, `pairs +0x488/+0x48c`, `actor list +0x564`, `flags +0x568`）、`WriteSaveItemStateFile`（0x27130，`float32 fields param_4+4..+0x1c then per-actor state`） |

**已确定的当前宿主键位**（`docs/first-level.md`，已手工验证）：右 Shift = 原 OK 键，Enter = 左功能键，Esc = 右功能键，左右 = 转身，上下 = 前进/后退。新设计不得与这套已验收的绑定冲突。

## 2. 已确定的设计约束

1. 输入层只能产生"原游戏本来就会收到的输入"，不能直接调用使用/合成/消耗结果。
2. 打开背包必须对应原版的物品界面路径，不能变成宿主自绘窗口；关闭必须走原状态迁移（参照 `CloseMapScreen` 写 state 10/1 的模式），而不是隐藏宿主图层。
3. 物品图标位置、分页、变体属于原数据（`picpos`/`tab`/`record+0x484`），宿主不得自造布局。
4. 合成判定只来自 `script` 内的 combine 表（`type/item1..item5/success/fail`），宿主不得内置任何配方。
5. 存档只在原写入路径发生（`.id`/`.itm`/`.dat` 族）。任何"便捷存档"都算越界。
6. 暂停只停止"由被暂停状态驱动的更新"，不能假设音频、影片、非世界 UI 一起停（见第 4 节）。
7. 原版 `key` 键位文件属于原游戏，宿主不得静默改写（见第 8 节）。

## 3. 输入架构

### 3.1 三层模型

```text
物理设备（键盘/鼠标/手柄）
  -> 宿主键位表（可配置，8 节）
  -> 宿主输入上下文栈（3.2，决定谁消费、谁暂停）
  -> 原输入动作标志（DispatchKeyAction 的动作位 / 场景输入字段）
  -> 原场景状态机（GameStateDispatch）
```

边界规则：**第三层只允许写"动作标志"和"输入字段"**，不写物品数组、不写存档、不推进场景状态。场景状态迁移只能由原 tick 函数在收到标志后自行完成。

### 3.2 输入上下文栈

栈式而非并列开关，避免"背包开着还能走动"这类泄漏。

| 上下文 | 进入条件 | 消费输入 | 世界 tick | 说明 |
| --- | --- | --- | --- | --- |
| `Scene` | 默认 | 移动/转向/光标/OK | 运行 | 原版可玩场景 |
| `SceneHoldItem` | 物品需要目标且已离开背包 | 光标移动 + 确认 + 取消 | 运行 | 保持"手持待用"状态，见 6.2 |
| `Dialogue` | 状态 5/6/0x24/0x27 | 推进/关闭 | 原状态决定 | 对白期不得插入背包 |
| `PauseMenu` | 状态 0x17 | 上下/确认/返回 | 停止 | 原版暂停菜单 |
| `Inventory` | Tab 或原"物品"软键 | 方向/点击/拖拽/Tab/Esc | 停止 | 见 4 节 |
| `ItemPuzzle` | 使用物品进入脚本小游戏（如 `InitMotorPuzzleUI`） | 该小游戏自己的输入 | 停止 | 输入权完全交给原 UI |
| `Video` | 原媒体播放 | 跳过语义按原版 | 不适用 | 独立线程；不参与世界挂起计数，见 11.1 |
| `SaveLoad`/`KeyConfig` | 场景模式 4/6/7 | 该屏自己的输入 | 停止 | 已有原实现，不重写 |

**推荐规则：**

- 只有栈顶上下文消费设备事件；下层收到的按键一律置为"释放"，防止按住状态卡死（对应 `DispatchKeyAction` 的 `param_3==2/3` 清除路径）。
- 指针按下时对焦窗口绑定捕获（pointer capture）。窗口失焦、Alt+Tab、拖拽移出窗口都合成一次"取消"，等价于 `param_3==2/3` 的清除，而不是保持按下位。
- 所有事件先入队，在帧边界统一取出后再调用原逻辑。原输入分发运行在 UI/定时器线程（`CEngine::StartTimers` 的 `CPeriodic` 500000us），**禁止**从 SDL 事件线程直接进入 `GameStateDispatch`。
- 事件带单调递增序号；同一序号只提交一次，用于 6.3 的"一次点击只使用一次"。

### 3.3 指针事件模型

指针不是新玩法，它是原"光标 + 确认"的连续化表达。

| 指针事件 | 原语义（推荐映射） |
| --- | --- |
| 移动 | 移动原光标位置（对应场景/UI 已有的光标坐标字段） |
| 左键按下 | 光标定位 + 记录按下点（不确认） |
| 左键抬起（同一目标、未超拖拽阈值） | 一次确认（等价 OK） |
| 左键抬起（不同目标、超阈值） | 一次拖拽提交（仅背包内） |
| 右键/Esc | 原"返回/取消" |
| 滚轮 | 仅列表滚动；不改变当前选中物品、不触发使用 |

【未验证】原光标位置字段与命中测试函数未在当前证据波内定位（`LoadMouseScript` 只证明存在光标模型）。实现前必须找到"光标坐标 → 目标 actor/物品"的原函数；找不到就退回键盘选择模型，不得自造拾取算法。

## 4. 暂停语义

### 4.1 暂停的定义

暂停 = 停止被暂停状态的每帧更新，不改变任何游戏状态值。实现上就是"不再进入该状态的 tick"，而不是给世界加一个 `paused` 标志去跳过内部逻辑。

证据支持这种"状态即暂停"的模型：暂停菜单本身就是 dispatch 状态 0x17，`PauseMenuRender` 只在 `state +0x1cdc==0x17` 时被调用；地图界面关闭靠写状态 10/1，而不是清一个暂停位。

### 4.2 分项语义（必须逐项定义，不能一句"暂停世界"带过）

| 子系统 | 背包打开时 | 依据 / 置信度 |
| --- | --- | --- |
| 场景 actor 运动与脚本推进 | 停止 | 【已确定】UI（含物品界面）是独立 dispatch 状态，见 §1 状态表；背包沿用该形态 |
| actor 状态倒计时（`TickActorStateCountdown`） | 停止 | 【推荐】它与场景 tick 同源；若原版背包状态仍 tick，则不得额外冻结 |
| 世界物理/碰撞/拾取判定 | 停止 | 【推荐】 |
| 音乐/音效 | **按原状态决定，默认不主动停** | 【已确定】`SaveSlotScreenTick` 显式 `ticks audio vtable +0x9c`，说明音频推进由各状态自行负责；背包状态原有行为需实测 |
| 影片（`SymbolWaveVideo`） | 不受背包影响 | 【已确定】媒体解码在独立 DLL/线程族 |
| 非世界 UI 动画（图标、闪烁） | 继续 | 【推荐】纯表现层，不改变判定 |
| 存档写入 | 禁止在背包打开期间发生 | 【推荐】避免半状态快照；存档仍只由存档状态触发 |
| 原输入对象 | 进入背包时清零一次，退出时再清零一次 | 【推荐】对应 `ResetInputState` 的语义，防按住键穿透 |

### 4.3 嵌套与恢复

- 暂停用**引用计数**：`PauseMenu` 与 `Inventory` 都持有"世界挂起"计数，退出其中一个不能提前恢复世界。
- 不允许在 `Dialogue`/`ItemPuzzle`/`Video` 之上打开背包；这些上下文的输入权不可被抢占。
- 背包打开期间收到存档请求（如自动存档点）必须延后到退出背包后执行，或在进入背包前完成；不得在背包状态中写盘。
- 退出背包必须走原关闭迁移（状态写入 + 输入复位 + 音频状态恢复），不得只销毁宿主 UI。

## 5. 装备选择（Q / E / F）

### 5.1 语义

装备 = 改变"当前选中物品"，**不产生使用**。三键都只做选择动作，结果必须与玩家在原界面里把光标移到该物品上等价。

| 键 | 行为 | 未持有时 |
| --- | --- | --- |
| `Q` | 选中镐子 | 保持当前选中不变；不切换到其它物品；不产生成功/失败反馈；可播报一次中性"未持有" |
| `E` | 选中弹弓 | 同上 |
| `F` | 选中"当前剧情互动明确需要"的物品 | 见 5.3 |

### 5.2 物品身份解析

【已确定】物品集合按 id 查询（`HasSceneItem(id)`、`RemoveItemRecordById(id)`），id 是脚本常量（如电机小游戏 id `0xb/0x16/0xc`）。

【推荐】Q/E 不硬编码 0x4b8 记录下标，也不按数组顺序取，而用一张**宿主只读别名表**：

```text
role: "pickaxe" -> item id（首次进入章节时从原物品表按 id/名称解析，解析结果缓存）
role: "slingshot" -> item id
```

- 别名表是宿主配置，不是游戏数据；不写回 `.itm`/`.id`，不新增物品。
- 解析失败（表中没有该物品）时 Q/E 一律按"未持有"处理，不得猜测。
- 【未验证】镐子/弹弓的稳定 id 值未在证据中确认（只有 0xb/0x16/0xc 属于电机类，0x714b 是查询测试值）。实现前必须从原物品表定位，并把结论写回本文。

### 5.3 `F` 的候选规则

- 候选来源限定为原数据：当前场景目标 actor（`scene+0x1ce8`）+ 原 rpt 脚本的 `item`/`poss`/`mouse` 字段 + 物品表 `NoResult`/`HasResult`。
- 唯一候选：选中，不自动使用。
- 多个候选：**不选**，保持原选中，最多给出"有多个可能"的非具体提示。禁止按"最先匹配"或"最常用"打破平局，那等于替玩家解题。
- 零候选：不动作，不报错。
- `F` 永远不能在背包关闭状态下直接消耗或推进剧情。

### 5.4 装备态是否入档

【未验证】`WriteSaveIdFile` 写入的是 `count/+0x488/+0x48c/actor list/flags`，`WriteSaveItemStateFile` 写入物品寄存器的 float 字段与每 actor 状态，两者都未见"当前选中物品"字段。

【推荐】装备选择作为**会话态**，不序列化；读档后回到原版读档后的默认选中。实现时若发现原版确实把选中写入 `.itm` 的 float 字段，则以原行为为准并更新本节。

## 6. 物品使用

### 6.1 一次性原则

一次确认 = 一次使用意图。实现要求：

- 使用中锁定输入（`InUse` 子状态），直到原 tick 结束该次使用或进入下一状态。
- 双击、按键重复、事件重放都不得产生第二次使用。用 3.2 的事件序号去重。
- 使用失败也消耗"这一次确认"，不自动重试。

### 6.2 两类物品的分流

分流必须来自原数据，不是宿主判断：

| 类型 | 判据 | 行为 |
| --- | --- | --- |
| 直接可用 | 原物品记录/脚本表明无需目标（如 `NoResult` 为空、无目标要求） | 在原界面内完成一次使用，进入原脚本后续状态 |
| 需要目标 | 原记录/脚本带目标要求（`HasResult`/`poss`/`mouse`） | 选中→关闭背包→回到 `SceneHoldItem`→光标指定目标→确认→原判定 |

在 `SceneHoldItem` 中：

- 只显示原版的待用表现（光标/物品图标），不新增准星或高亮提示。
- 取消（右键/Esc）必须回到使用前状态：物品仍在、选中不变、无消耗、无脚本副作用。
- 目标不合法时交给原判定的失败分支；宿主不得提前拦截或改写提示。

### 6.3 与脚本的关系

【推荐】使用路径只允许两种注入点，按优先级：

1. 合成/使用界面的原输入动作（`DispatchKeyAction` 的动作位，以及 `ItemInfoPageTick` 那类 UI 输入字段）。
2. 原 UI 的确认标志。

禁止：直接调用 `ProcessItemScript`、直接调用 `HasSceneItem` 来"预判成功"、直接调用 `RemoveItemRecordById` 来消耗。

## 7. 拖拽合成

### 7.1 位置语义

原版合成界面已有两个槽位资源：`combcurr`（当前）与 `combcurw`（与之组合），外加 `combframe`、`iconsuc`、`iconfail`。拖拽 A→B 应落到这两个槽位上，**复用原槽位与图标**，不自绘合成面板。

【推断】`combcurr`/`combcurw` 就是"原料/目标"两槽，依据仅为资源命名与 `LoadItemSelectSprites` 的加载顺序；需在实现前用界面实测确认槽位字段。

### 7.2 状态机

| 状态 | 进入 | 允许的转移 | 副作用 |
| --- | --- | --- | --- |
| `Idle` | 背包打开 | `PressCandidate` | 无 |
| `PressCandidate` | 左键按下（命中物品） | `Dragging`（超阈值）/ `ClickCommit`（原地抬起）/ `Idle`（取消） | 无；只记录按下点与记录索引 |
| `Dragging` | 位移超阈值 | `HoverTarget`/`Cancel` | 无；只移动视觉拖影 |
| `HoverTarget` | 指针落在另一物品上 | `DropPending`（抬起）/ `Cancel` | 无 |
| `DropPending` | 抬起在有效目标上 | `Commit` | 冻结输入，生成**一个**提交序号 |
| `Commit` | 交给原合成判定 | `Success` / `Fail` | 只由原判定写物品数组 |
| `Success` | 原成功分支完成 | `Idle` | 原脚本结果、原图标、原音效 |
| `Fail` | 原失败分支完成 | `Restore` | 仅原失败提示；无消耗 |
| `Cancel` | Esc/右键/失焦/拖到空白 | `Restore` | 无 |
| `Restore` | 失败或取消 | `Idle` | 位置、选中、顺序、图标、动画复位 |
| `ClickCommit` | 原地抬起 | `Idle`（或进入 `6.2`） | 一次单击使用 |

约束：

- 只有 `DropPending` 会进入原合成路径；`Restore` 路径绝不触发脚本。
- `Commit` 期间不接受新的按下事件（避免半提交叠加）。
- 拖拽阈值用宿主 DPI 无关单位，默认 4 CSS px，可配置。

### 7.3 失败回滚的具体对象

回滚必须覆盖以下全部，而不是只把图标移回去：

| 对象 | 回滚要求 | 依据 |
| --- | --- | --- |
| 两槽的占用与顺序 | 与提交前逐字节一致（id 序列 + 数量） | 物品数组可交换、删除（`SwapItemRecords`/`RemoveItemRecordById`） |
| 变体选中字节 `+0x74+i` | 回到提交前值 | `ItemPictureSelectTick` 会改写选中字节 |
| `engine+0x224` 变体索引 | 回到提交前值 | 同上 |
| 物品数组容量 | 不变或合法扩容；不得因失败留下空洞 | `GrowItemRecordArray` 头部 `{0x4b8,count,capacity}` |
| 待用/手持标记 | 清除 | 否则退出背包后残留待用状态 |
| 播放中的合成动画与音效 | 允许播完，但不得继续持有输入锁 | 【推荐】 |
| 存档文件 | 不写 | 失败不是存档事件 |

推荐实现顺序：提交前对"两槽 + 选中索引 + 变体值"做一次轻量快照（只读拷贝，不回写）；提交交给原判定；若原判定返回失败或没有产生任何数组变化，则按快照核对并只修复被动过的字段。**不要**用自己构造的成功/失败结果去覆盖原结果。

### 7.4 与双击/单击的边界

- 同一物品上按下并抬起、未超阈值 → `ClickCommit`（一次使用），不得被识别为"自己拖给自己"的合成尝试。
- A 拖到 A 自身上：视为取消（`Cancel`），因为原合成表要求不同 `itemN` 槽，宿主不额外定义自合成。
- 拖到已占用槽：交给原判定（原表可能支持多原料），宿主不预判。
- 拖到非物品区：取消，不弹提示。

## 8. 原脚本 / 存档调用边界

### 8.1 允许与禁止

| 操作 | 允许 | 禁止 |
| --- | --- | --- |
| 读物品集合 | 只读遍历 `engine+0x530` 的三组数组 + 计数（`HasSceneItem` 同源数据） | 修改数组、重排数组、按自定顺序展示后回写 |
| 触发使用 | 注入原 UI 确认动作 | 调用 `ProcessItemScript`、伪造成功状态、跳过小游戏 |
| 触发合成 | 走原合成界面/判定 | 宿主内置配方、直接 `AppendItemRecord`/`RemoveItemRecordById` |
| 关闭背包 | 走原关闭状态迁移 + 输入复位 | 仅隐藏宿主图层、仅清宿主暂停位 |
| 存档 | 由原存档状态调用 `WriteSaveIdFile`/`WriteSaveItemStateFile` | 自写 `.itm`/`.id`/`.dat`/`.idx`/`.pub`、改 `tmp.id`、静默补字段 |
| 键位 | 宿主键位表、光标/指针映射 | 改写原 `key` 文件以"顺手"加 PC 键；占用原版保留键码导致原屏不可操作 |

### 8.2 只读视图模型（推荐）

背包 UI 只需要一个只读视图模型，每帧或按失效标记重建：

```text
ItemView {
  listIndex, recordIndex,        // 定位用，不对外暴露为稳定 id
  id,                            // 原物品 id
  tab, picpos,                   // 来自 item 表
  name, info, desc,              // 原文本，直接显示，不重写
  variantCount, variantIndex,    // 来自 +0x484 / +0x224 / +0x74+i
  usableDirect, needsTarget      // 来自原记录/脚本标志，只读
}
```

- 视图模型不可写；写操作一律转成输入动作。
- 重建失败（数组正在被原脚本改写）时，本帧不提交拖拽，保持 `Idle`。
- 【未验证】`engine+0x530` 三组数组各自代表"背包/已用/临时"还是别的划分。在确认前，禁止把三组合并展示、禁止跨组拖拽。

### 8.3 存档往返

- 背包开关、拖拽中间态、装备选中都不应出现在存档里。
- 合成/使用产生的结果必须能通过原存读档往返：存 → 退 → 读 → 物品集合一致。
- 只验收 `runtime.md` 已覆盖的槽位 `0`；其它槽位仍属未验证范围。

## 9. 可配置键位

### 9.1 三层配置

| 层 | 归属 | 落盘 | 说明 |
| --- | --- | --- | --- |
| 原游戏键位 | 原游戏 | `key`（原格式，`ReadKeyConfigFile`/`WriteKeyConfigFile`） | 只能在原键位界面里改；宿主不代写 |
| 宿主 PC 键位 | 宿主 | 宿主自有配置文件（版本化，含 `version` 字段） | Q/E/F/Tab/鼠标/手柄映射；可整体重置为默认 |
| 辅助/可访问性开关 | 宿主 | 同一宿主配置文件 | 见第 10 节 |

冲突规则：

- 宿主键位与原 `key` 绑定重叠时，**场景移动/OK/软键仍以原绑定为准**，宿主只补足原版没有的动作（Q/E/F/Tab/指针）。
- 检测到重叠必须显式提示并让玩家选择，不得静默覆盖。
- 必须至少保留一组不可解绑的动作：确认、取消/返回。防止玩家把自己锁在背包或对白里。
- 配置解析失败时回退默认绑定并记录一次日志，不阻止启动。

### 9.2 默认布局

| 输入 | 动作 | 备注 |
| --- | --- | --- |
| `Q` | 选中镐子 | 未持有：不变更 |
| `E` | 选中弹弓 | 未持有：不变更 |
| `F` | 选中剧情所需物品 | 只在唯一候选时生效 |
| `Tab` | 开/关背包 | 等价原"物品"软键路径 |
| 左键 | 光标定位 + 确认 | 见 3.3 |
| 右键 | 取消/返回 | 与原右软键等价 |
| 滚轮 | 列表滚动 | 不改选中 |
| 已验收键位 | 保持 `docs/first-level.md` 的现状 | 不得回归 |

### 9.3 手柄/触控板

【推荐】手柄按键走同一动作表；模拟量输入不做新玩法（不改移动/转向规则），只用于等价数字方向。触控板滚动与滚轮同义。

## 10. 可访问性

目标：不改变任何判定，只提供等价输入路径与表现选项。

| 项 | 要求 | 不改变规则的理由 |
| --- | --- | --- |
| 键盘完整路径 | 每个鼠标操作都有键盘等价物（含合成） | 全部落到原确认/取消动作 |
| 鼠标完整路径 | 每个键盘操作都能点出来（含 Q/E/F 的等价按钮） | 同上 |
| 拖拽替代 | 两段式选择："选中 A → 选中 B → 确认合成" | 与原双槽语义一致（`combcurr`/`combcurw`） |
| 按住 vs 切换 | 需要持续按住的动作用"切换模式"替代 | 只改输入形态 |
| 重复按键去抖 | 系统级 key repeat 不得产生额外确认 | 3.2 的序号去重 |
| 成功/失败反馈 | 图标 + 文本双通道，不只靠颜色 | 资源仍是原 `iconsuc`/`iconfail` |
| 动画减速/关闭 | 表现层可关，判定时序不变 | 不影响脚本计时 |
| 文字可读性 | 允许宿主放大 HUD/菜单文字 | 【未验证】原字体是位图字形（`DrawAlphaGlyph`/`DrawWideGlyph`），无可缩放字形；放大方案需单独验证，不得以重绘字体替代原资产 |
| 屏幕阅读 | 本阶段不做 | 原版无 TTS；新增朗读等于新增表现系统 |
| 键位重映射 | 全覆盖，含 Tab/Q/E/F | 见 9.1 |

明确不做的"可访问性"：自动瞄准目标、自动选择正确物品、自动完成合成、跳过原判定。这些都属于绕过游戏规则。

## 11. 状态机汇总

### 11.1 输入上下文（简化）

```text
Scene --Tab/物品软键--> Inventory --Tab/Esc/关闭迁移--> Scene
Scene --使用需要目标的物品--> SceneHoldItem --取消--> Scene
Scene --互动进入对白--> Dialogue --结束--> Scene
Scene --菜单--> PauseMenu --选项--> Scene | SaveLoad | KeyConfig | ...
Scene --使用物品进入小游戏--> ItemPuzzle --原结果--> Scene | Dialogue
```

不变量：

1. `Inventory`、`PauseMenu`、`SaveLoad`、`KeyConfig`、`ItemPuzzle` 同时最多存在一个。
2. 任何上下文退出时都执行：输入清零 → 世界挂起计数递减 → 原关闭迁移。
3. `Video` 不参与本栈的暂停计数。

### 11.2 拖拽合成

见 7.2 表；关键不变量：只有 `DropPending → Commit` 一条边能触达原脚本。

### 11.3 使用

```text
Bag: Selected --确认--> InUse(锁定) --原结果--> Bag | 直接可用结果
Bag: Selected --确认(需要目标)--> SceneHoldItem --确认目标--> InUse(锁定) --原结果--> Scene
                              \--取消--> Bag(物品与选中不变)
```

## 13. 风险与未验证项

| # | 项 | 影响 | 处置 |
| --- | --- | --- | --- |
| 1 | 原背包界面的具体状态号与入口未定位 | Tab 可能接错状态 | 实现前从"物品"软键路径追到具体 state，不得先写 UI 再找入口 |
| 2 | 光标坐标字段与命中测试函数未定位 | 点击/拖拽无法忠实映射 | 先定位，再决定是否支持指针；否则退回键盘选择 |

| 4 | 两个输入复位函数（0x3ff9c / 0x3feac）归属未定 | 退出时可能清错字段 | 用实测确定背包用哪一个；两者都清零时也要确认顺序 |
| 5 | 装备态是否入档未定 | 读档行为可能不一致 | 以原版实测为准，不先实现"保存选中" |

| 8 | 背包状态的音频行为未实测 | 可能误停音乐 | 以原版该状态实测为准（4.2） |
| 9 | 位图字体无缩放路径 | 文字放大方案可能违背"不重绘资产" | 放大只做几何缩放并单独验收；不替换字形 |

## 14. 开放问题（需决策或补证据）

1. `Tab` 是否直接复用原"物品"软键动作，还是需要一个宿主侧入口再触发同一状态？（推荐前者：少一层偏差。）
2. 拖拽失败时是否允许播放原失败音效？推荐允许——它来自原资源，且不改变判定。
3. 是否允许在背包中使用"装备快捷键"（Q/E/F）？推荐允许：它只改变选中，不触发使用；但必须在实测确认不会与原 UI 光标冲突后启用。
4. 手柄模拟量是否需要死区配置？推荐只做等价数字映射，不引入新移动手感。
5. 是否需要"上次选中物品"的会话记忆？推荐不做，避免与读档默认值混淆。
