# 引擎节拍与渲染解耦设计

状态：调查完成，尚未实现。证据标签：[静态] 地址或文件行；[实测] 本机日志；[推断]；[未验证]。
前置：渲染已由用户接受。WASD 平移与独立鼠标视角排在本文方案之后，本文不实现输入。

## 1. 已确认的节拍

- 游戏没有 dt。移动、倒计时、动画按调用次数推进。[静态]
- 帧入口 `GameSceneProcessFrame` 0x698cc，由 `TimerTick` 0x8c750 经 `TitleScreenTick` 0x59948 驱动，再用 `RTimer::After` 重挂。[静态]
- 延时 = `120000 µs - (now - prev_end)`，下限 100 µs（0x59a00–0x59a34、0x59bb0–0x59bcc）。`0x59cf8` 的 64 位常量实读为 120000。[静态][实测]
- 3D 阶段（`session+0x1cdc == 0xa`）实测 arm 在 100 µs 与约 109–113 ms 之间交替，帧间隔 15/119 ms，均值约 67 ms，约 15 fps。native、Vulkan、跳过光栅三种模式一致。[实测]
- 宿主未改变该延时；present 在游戏线程同步执行，先吃掉定时器余量，不是节拍来源。Vulkan 场景额外开销约 3.7 ms/帧。[实测]
- 原机的真实帧率与唤醒间隔：[未验证]。

## 2. 目标

逻辑 tick 保持原延时与原语义。显示按刷新率更高频率重绘，画面中的相机/角色在相邻两个逻辑状态间插值。不改剧情、碰撞、脚本、存档。

## 3. 调查结论（约束）

1. 逻辑与绘制交错在同一次 `GameSceneProcessFrame` 内：`RenderSceneActor` 0x43dc0 在 Ghidra 行 53075，早于 `FUN_00068860`（53130）与 `GameStateDispatch`（53134）。目前没有独立 draw 入口。
2. 不能重跑 guest 绘制链：
   - `RenderSceneActor` 置 `player+0x5eb = 5`，`GameSceneCompositeFrame` 每次调用递减它（Ghidra 52419）。重复绘制会缩短闪光时长。
   - flash 循环和 state 0x1a 后处理直接改 `session+0x2a0` 的像素。
   - 重跑 0x43ad8/0x43dc0 会把插值值写回 AABB 与 actor+0x580，污染碰撞。
   - 重入还会触发 `host_tris_begin` 与 `serial++`，使 `host_scene_alpha_run` 失效。
3. 只有 `DrawSceneGeometry` 0x63194 每次从相机位置与 `viewport+0x14c/0x150/0x154` 重建视图矩阵，不缓存。[静态]
4. 不能瞬时覆盖的字段：actor/子弹的 `+0x250..+0x264`、`+0x278` 朝向、AABB、动画帧表。可作为插值对的是 `(+0x250/254/258, +0x25c/260/264)`；朝向没有 guest 侧上一 tick 快照，需宿主自存。
5. `0x711f0` 只对三角形记录里的预投影 XY 做缩放；`renderer+0x44` 是按深度索引查询的倒数表，不是世界顶点数组。E32 中的 `0x712f8` 确有定点顶点变换，但不在本次计时构建生成的 AOT 路径中，不能把它当作运行时捕获点。

## 4. 推荐架构

- 逻辑 tick 照旧由 guest 定时器触发，不改 `RTimer::After`。
- 每个逻辑帧结束，宿主快照：最终合成帧、`host_tris_frame`、插值对和朝向。
- 在 `next_timer_event`（recomp_start.py ~3205）的空闲窗口中，按显示刷新时刻执行仅宿主的渲染帧：不调用 guest，不改 `serial`。
- 真正的相机插值需要 GPU 世界到相机变换：宿主持有世界空间顶点和视图矩阵输入后，才能用插值相机重投影。在此之前，空闲帧只能重复呈现最近一帧。
- 呈现的 acquire/fence 移出调度线程，或设时间预算，避免 FIFO 阻塞推迟 timer 派发。

## 5. 实现顺序（每步可独立验证）

1. 读常量并确认 `After` 的 `nanosleep` 分支与两个 SDL 事件消费者（`window_gc.h:1349`、`pump_window_input`）哪个在游戏中运行。常量已确认；其余 [未验证]。
2. 逻辑帧末快照，无行为变化。验证：`ISLAND_VK_SCENE_CHECK=1` 匹配数不变。
3. 空闲窗口仅宿主重复呈现。验证：timer 派发时间不变；空闲期呈现频率达刷新率。
4. GPU 世界到相机变换（前置：捕获世界空间顶点与视图矩阵输入）。验证：逻辑帧上与 guest 输出一致。
5. 插值相机重投影，`session+0x22c` 位置与朝向仅作宿主侧输入，不写回 guest。
6. acquire/fence 异步化，验证 60 Hz 下 timer 抖动。

## 7. Vulkan 定点变换原型

`vk_scene_transform` 按 E32 `0x712f8` 的算术执行三行点积：32 位回绕乘加、算术右移 8 位、再回绕加平移。`vk_scene_test --self-test` 在 llvmpipe 上通过逐字 XYZ 对照，覆盖负数、溢出、跨工作组与重复派发；同次运行的已有场景回归通过，日志未见 Vulkan 同步验证错误。

此测试只验证该定点算法，不证明游戏场景使用它。原型未连接到游戏帧，不改变当前渲染或计时；接线前必须定位实际生产者、验证坐标和裁剪语义，再用真实批次逐点对照。

已定位的运行路径捕获点是 `DrawSceneGeometry` 的 `0x631fc → 0x70104`：`r0` 为 renderer，`r1` 指向 `session+0x138` 的相机位置。该调用复制三个字到 renderer `+0x447bc/+0x447c0/+0x447c4`；位置已过浮点到整数转换，不是浮点位模式。`0x707b4–0x70800` 读取同一组字段参与视图平移计算。该入口只能提供相机位置，尚不能提供用于逐点配对的世界 XYZ、完整矩阵或裁剪前输出，因此未启用运行时替换。

`0x7015c` 先把视图与对象变换组合成逐对象的 `0x30` 字节定点矩阵，筛出对象后，通过对象虚表 `+8` 把矩阵交给各自的三角形生成器（反编译 56681–56782）。因此真实批次对照应在这些生成器内部配对顶点，而不是在投影入口反推世界坐标，也不能把 `0x712f8` 的右移 8 位直接套给它们。

其中一个生成器 `0x88438` 对应 E32 虚表槽 `0x93990`，并调用 `0x8a104`。后者从 `object+0x138` 指向的数组读取有符号 16 位模型坐标，从 `object+0x134` 读取组合矩阵，将三个 32 位分量写入 `object+0x13c` 指向的数组。根据 lifted 指令 `0x8a1cc–0x8a23c`，每个分量是 `ASR(wrap(translation + ASR(wrap(dot), shift)), shift)`，`shift` 来自对象 `+0x7c`。这是模型到相机的组合变换，不是 `0x712f8` 的单次右移算法。

`ISLAND_VK_MESH_CHECK=1` 在 `0x8a250`（最后一次 XYZ 写入之后、裁剪之前）启用只读抽样。每个合成帧最多检查一批，每次运行最多八批。GPU 结果只用于比较，guest 输出仍驱动裁剪和投影。独立自测已覆盖双移位算术的 0、1、8、31 位移和非法位移拒绝。

序章有限冒烟（llvmpipe，Vulkan 同步验证开启）：帧 497–504 各抽样 674 个顶点，`shift=9`，累计 5392 个顶点、16176 个 XYZ 分量，全部与 guest 逐字一致；场景继续提交，日志未见验证错误。此结果只覆盖每帧第一个符合条件的模型批次，不覆盖其他生成器、第一章或裁剪后新生成的顶点，也不代表帧率提升。
