# PC 渲染设计说明（现代 GPU 3D 管线）

本文是 [`pc-modernization.md`](pc-modernization.md)「现代 3D 管线」一节的子系统设计说明，供主文档链接或整合。

本文只定义渲染侧的需求、接口边界、风险和验收方式，不改玩法、不改脚本/碰撞/存档语义，也不锁定具体图形 API。文中的「验证」指画面对照与缓冲转储，不指新增玩法测试。

## 0. 证据等级

| 标记 | 含义 | 出处 |
| --- | --- | --- |
| `[静态]` | 已从反编译与符号表确认的结构或常量 | `build/RendererSymbols.tsv`、`build/GameFull.tsv`、`build/SymbolWaveGeometry.tsv`、`build/SymbolWaveScene.tsv`、`build/SymbolWaveVideo.tsv`、`build/ghidra-annotated/IsLand_3rd.exe.c` |
| `[运行]` | 已在宿主运行时观察到 | `docs/runtime.md`、`tools/window_gc.h` |
| `[推断]` | 由结构推出、尚无对照 | 必须验证后才可写成事实 |
| `[待定]` | 必须逆向或 A/B 对照才能决定 | 实现前阻塞项 |

约定：地址写作 `0x63194 DrawSceneGeometry`，必要时附字段偏移（`renderer+0x38`）。偏移均为原版对象的字节偏移，不是 PC 结构体布局。

## 1. 不变量

以下在任何阶段都不得破坏；它们优先于任何「更正确」的渲染做法。

1. 帧内层级顺序：3D 不透明层 → 遮罩/透明层合成 → HUD 与对白 → 全屏调色。顺序可变的前提是对照通过。`[静态]`（`0x68ea0 GameSceneCompositeFrame`）
2. 提交集合与提交顺序由 guest 决定：BSP 可见性、实体剔除、渲染列表、深度键排序全部沿用 guest 结果，host 不得自行增删或重排。`[静态]`
3. 逐三角形常量 alpha、颜色键 `0xF81F`、逐对象明暗值属于可观察外观，不得「顺手修正」。`[静态]`
4. 资产内容不变：贴图尺寸、调色板、多边形数量、UV、蒙版形状均不重制。`[静态]` + 主文档
5. 镜头语义不变：位置、朝向、视场、近远裁剪、镜头动画曲线沿用 guest 数值。
6. 渲染设置只影响像素：雾、AA、过滤、画幅都不得改变碰撞、交互距离、AI、脚本分支或存档。
7. guest 的软件渲染路径永久保留为对照基线，可用运行时开关切回。

## 2. 原版渲染管线（现状重建）

### 2.1 每帧顺序 `[静态]`

`0x68ea0 GameSceneCompositeFrame` 依次调用：

| 步骤 | 函数 | 作用 |
| --- | --- | --- |
| 1 | `0x63194 DrawSceneGeometry` | 清屏、设相机、提交并光栅化全部 3D 三角形 |
| 2 | 内联循环 | 受击全屏提亮：把玩家 `+0x5eb` 计数加到帧缓冲的 R/G 分量 |
| 3 | `0x62f08 CompositeLightingBuffer` | 把遮罩层按 alpha 合成进帧缓冲，带深度键门限 |
| 4 | `0x69108 DrawHud` | HP 栏、图标、按键提示等索引位图 blit |
| 5 | 内联循环（状态 `0x1a`） | 全屏逐像素调色/淡出 |
| 6 | `0x38e80` | 会话逻辑帧（输入/状态推进） |

新增的 3D 后端必须嵌入第 1–3 步的语义，不能把 HUD 或调色并入 3D 通道。第 2、5 步是全帧后处理，见 §4.12。

### 2.2 缓冲区 `[静态]`

`0x6f720 InitRendererBuffers` 按视口尺寸分配、`0x63194` 每帧清零（清零值全为 0，即黑）：

| 字段 | 规格 | 已确认用途 |
| --- | --- | --- |
| `(session+0x2a0)+4` | `w*h*2`，RGB565 | 可见帧缓冲；3D 与 2D 共用的最终画布 |
| `renderer+0x34` | `w*h*4`，int32 | 逐像素深度键 |
| `renderer+0x38` | `w*h*2`，RGB565 | 遮罩层颜色（合成源） |
| `renderer+0x3c` | `w*h*4`，int32 | 遮罩层深度键 |
| `renderer+0x40` | `w*h*1`，byte | 遮罩层 alpha |

`[推断]` 「不透明几何直接写帧缓冲 + 深度；模式 6 写遮罩层三件套」这一归属由 `0x62f08` 的读取端（源 = `+0x38`，目标 = 帧缓冲，权重 = `+0x40`）与模式 6 光栅器的写入端共同得出。间接调用点的实参在反编译中丢失（`DrawSceneGeometry` 里的 vtable 调用只显示 4 个实参，而被调函数有 6–8 个形参），因此这一步必须用固定帧四缓冲转储确认。`[待定]`

### 2.3 场景提交 `[静态]`

| 阶段 | 函数 | 结论 |
| --- | --- | --- |
| 可见性 | `0x51580 CollectVisibleEntities` | 从相机点遍历 BSP，标记单元位图，再按实体法线·位置点积筛选精灵 |
| 分叶 | `0x519ac BucketEntitiesByLeaf` | 预计算每个 BSP 叶的实体索引 |
| 渲染列表 | `0x6fd70 AppendRenderListEntry` | 容量 `+8`，计数 `+0xc`，数组 `+0x10`；满则丢弃 |
| 逐对象矩阵 | 各对象 vtable slot 2 → `renderer+0x447ac[]` | 每条 0x30 字节基矩阵（`0x6fdf0 BuildBillboardMatrix` 用 12 位角度表） |
| 角色渲染条目 | `0x43dc0 RenderSceneActor` | 单对象准备：用相机到对象的线段与全部实体 bbox 做扫掠（`0x547d0`）修正可见距离，再设 `+0x7c=9`、`+0x84=6`、`+0x172=0x40`、`+0x80=1`，写颜色（`0x8a25c`）并入列 |
| 三角形生成 | `0x88438 BuildObjectTriangles` | 生成 0x58 字节记录；`+0x48` 取对象 `+0x84`，`+0x49` 取 `+0x16`，同时写深度键 |
| 排序 | `0x6f1cc SortDepthPairs` | 对深度键数组做快排，负载为三角形索引 |
| 投影 | `0x711f0 ProjectTriangleBatch` | 逐顶点算屏幕坐标与视口偏移 |

同一批三角形有两个提交分支：默认按索引升序提交；当 `session+0x1cdc==8` 且 `+0x554==0x13` 时按深度键降序（由远及近）提交。`[静态]` 该特例必须原样保留，见 §4.1。

### 2.4 顶点与投影 `[静态]`

- 顶点变换：`0x712f8 TransformVerticesFixed` 用 3×3 定点矩阵（`>>8`）乘顶点后加原点，顶点步长 `0xc`。
- 相机：位置 3 个浮点写入 `renderer+0x447bc/0x447c0/0x447c4`（`0x70104`），视点偏移 3 个 dword 写入 `+0x447c8/0x447cc/0x447d0`（`0x70130`），变换块 0xc4 字节由 `0x6f0b8` 提供。
- 朝向：`viewport+0x14c/0x150/0x154` 三个浮点量参与朝向基构造；`DrawSceneGeometry` 把它们乘 `512.0`（`0x44000000`）换算成 12 位表索引（`0xfff` 一周）后查 sin/cos 表，得到 3×3 基。`[推断]` 三个量的单位与符号约定（是否就是欧拉角、yaw 的 ±0x200 取反含义）未经确认，实现前需用固定镜头对照。
- 投影：`0x6ede0 SetProjection` 由三个角度和视口尺度生成缩放/偏移表；顶点深度索引查 70000 项倒数表（`0x6f720`，`0x10000000/i`），屏幕坐标 `= origin + (scale * coord >> 16)`，其中 `scale = (倒数表项 >> 12) * viewport+0x130`。
- 视口：`0x6eae4 SetViewport` 存 `+0xd0=w`、`+0xd4=h`、`+0xd8=w`、`+0xdc=h`、`+0x104=2000`（远裁剪）、`+0x154=1.0`；`+0x130 = f(min(w,h))`。
- 屏幕原点：`renderer+0x20 = w/2`，`renderer+0x24 = viewport+0x10c`（不是 `h/2` 的直接表达式，语义 `[待定]`）。

关键后果：**投影尺度只由 `min(w,h)` 决定且两轴同尺度**。改变画幅比例而不改投影，等于拉伸；要保持像素比例，必须锁定画幅或显式引入 X 轴独立缩放（§4.5）。

### 2.5 光栅分派 `[静态]`

`DrawSceneGeometry` 按三角形记录 `+0x48` 的渲染模式分派，`+0x49` 非 0 的三角形整条跳过（`ProjectTriangleBatch` 用 `0x64` 标记剔除）：

| 模式 | 入口 | 已确认行为 |
| --- | --- | --- |
| `0` | vtable `0x93958[0]` = `0x83fa8` | 纹理不透明；写颜色（步长 2）与深度（步长 4），`existing_depth < new_depth` 才写 |
| `6` | vtable `0x93958[1]` = `0x85bb0` | 颜色键遮挡；采样到 `0xF81F` 跳过该像素；写颜色、层深度键、逐像素 alpha 常量 |
| `4` | `0x7d8ac` | 单纹理；bpp `tex+0x10`、宽 `tex+0x14`、数据 `tex+0` |
| `5` | `0x7f854` | 双纹理（两张位图在同一描述符 `tex+0`/`tex+4`；索引来自 `map+0x168/+0x16c`） |
| 其它 | `0x76ad4` | 平面着色扫描线，不采样纹理 |

采样为 16.16 定点 UV，`>>16` 取最近邻；透视校正通过深度索引查倒数表（`param_1+0x44 + (depth>>9)*4`）实现。`[静态]` 表项钳位与溢出规则 `[待定]`。

深度方向：现有值小于新值即写，**数值越大越靠前**。`[静态]`

### 2.6 合成 `[静态]`

`0x62f08` 逐像素：`dst = dst + ((src - dst) * (alpha >> 3) >> 5)`，在 RGB565 上用 `0x7e0f81f` 做双通道并行掩码，等价于按 `alpha/256` 线性插值。门限为 `depth(+0x34) < key(+0x3c) + 50000`；`session+0x1cc0` 非 0 的分支在合成后把 `depth` 抬到 `key+50000`，使重复合成幂等。`50000` 的偏置量纲 `[待定]`。

### 2.7 2D 与 HUD `[静态]`

| 函数 | 规则 |
| --- | --- |
| `0x8a888 BlitIndexedBitmapScaled` | 8bpp 调色板 → RGB565，调色板项 `0xF81F` 视为透明，带裁剪与缩放 |
| `0x8b444 BlendBitmapAlpha` | 逐像素 alpha `0..0x100` 混合 RGB565，`0xF81F` 透明 |
| `0x8b69c RecolorPixels` | 裁剪区内按值替换像素（选中/禁用态） |
| `0x8bd34 BlitMaskBytes` | 单字节掩码 blit |
| `0x69108 DrawHud` | 坐标由视口宽高乘比例系数（`DAT_000696b0 >> 0x25`）与固定偏移组合；同一函数里两种写法并存 |
| `0x29fb0 DrawSpanTextured` | 2D 纹理跨距的浮点 U/V 逐像素插值 |
| `0x2a4e4` / `0x2a6a4` / `0x2a1bc` | 字母/数字/宽字符字形 blit |

HUD 坐标已是「屏幕尺寸 × 比例」，不是固定像素；但部分路径仍用固定偏移，因此宽屏锚定必须逐尺寸实测（§4.10）。

### 2.8 影片 `[静态]`

影片由 guest 内 MPEG-4/AVI 解码，输出 YUV420 后转换：`0x31ade8`（→RGB24）、`0x31b05c`（→RGB565，显示模式 `10`/`7` 对应 `0xf0`/`0xf8`/`0xfc` 打包），系数来自 `0x31ac80` 的 BT.601 有限范围表；`0x31a734` 支持 0/90/180/270 旋转。`0x5bfc4 CreateScreenBuffers` 按屏宽选择 `Video\176x208\` 或 `Video\240x320\`。素材只有这两套分辨率，宽屏不能拉伸（§4.11）。

### 2.9 已知缺口

`[运行]` 当前首场景仍有 `texture\scene\` 贴图缺失警告。渲染对照的基线因此本身不完整；不得用 `texture\sd2\` 同名文件自动替代（`docs/runtime.md`）。缺失资产不属于渲染迁移范围，但必须出现在对照报告的「已知差异」里。

## 3. 目标架构与接口边界

### 3.1 分层

```text
guest 逻辑/脚本/碰撞/镜头（原样执行）
  ├─ 可见性、渲染列表、对象矩阵、深度键  ← guest 决定，host 只读
  └─ 三角形批次（0x58 记录）/ 2D blit 调用
        ↓ 接入点 A/B/C
host 渲染后端（GPU 变换、裁剪、光栅、深度、采样、混合）
        ↓
合成后的 3D 图像写回 guest 帧缓冲
        ↓
guest 继续执行 HUD / 对白 / 调色（原样），host 上传并呈现
```

「写回 guest 帧缓冲」是本设计的核心取舍：帧缓冲只有 `176×208×2 = 73 216` 字节，60 fps 下约 4.4 MB/s，读写回传成本可忽略，换取的是 2D 层、对白框、全屏后处理零改动地保持原语义。

### 3.2 三个接入点

| 接入点 | 位置 | GPU 负责 | guest 仍负责 | 风险 | 用途 |
| --- | --- | --- | --- | --- | --- |
| A 光栅器替换 | 渲染器 vtable `0x93958[0..3]` | 屏幕空间三角形、采样、深度、颜色键、alpha 写层 | 可见性、排序、顶点变换、投影、裁剪 | 低；像素级可直接对照 | 首个 GPU 阶段 |
| B 批次接管 | `0x711f0 ProjectTriangleBatch` 前后 | 近裁剪、透视除法、光栅化、深度 | 可见性、排序、顶点变换、深度键 | 中；定点与浮点结果有细差 | 第二阶段 |
| C 场景接管 | `0x68ea0` 帧函数处替换第 1–3 步 | 完整 3D 管线 + 两层合成 | 可见性判定、排序键、对象矩阵 | 高；必须完全复现顺序与合成 | 目标形态 |

推荐 A → B → C，逐级保留上一级为回退路径。理由：A 的输入是 guest 已算好的屏幕坐标，任何差异都能归因到采样/深度/混合；B、C 会同时引入投影与裁剪差异，若一开始就跳到 C，出错时无法区分是几何误差还是合成误差。

### 3.3 接口契约

host 后端只接受下面这些只读数据；所有字段由 guest 写入，host 不反向写 guest 状态。

| 项 | 内容 | 证据 |
| --- | --- | --- |
| 帧 | 起止、视口 `w/h`、可见帧缓冲指针、清屏值 0 | `0x63194` |
| 相机 | 位置 xyz（float）、视点偏移 xyz、朝向角三值（×512 → 12 位）、变换块 0xc4 | `0x70104`、`0x70130`、`0x6f0b8`、`0x63194` |
| 投影 | 尺度 `viewport+0x130`、原点 `(w/2, viewport+0x10c)`、远裁剪 2000、倒数表 | `0x6eae4`、`0x6ede0`、`0x6f720` |
| 对象 | 0x30 字节基矩阵 + 原点、对象 `+0x84` 渲染模式、`+0x16` 标志、颜色三值、`+0x172` 明暗/闪值 | `0x6fdf0`、`0x88438`、`0x8a25c` |
| 三角形 | 0x58 字节记录：3×(0x18 顶点)，`+0`/`+4` 屏幕 xy，`+8`/`+0x20`/`+0x38` 深度索引，`+0x48` 模式，`+0x49` 丢弃标志 | `0x711f0`、`0x88438`、`0x63194` |
| 材质 | 调色板位图（bpp/宽/data）、第二纹理、颜色键 `0xF81F`、逐三角形 alpha | `0x7d8ac`、`0x7f854`、`0x85bb0`、`0x6d1b4` |
| 2D | 调色板 blit 矩形、缩放、透明键、alpha `0..0x100`、改色对 | `0x8a888`、`0x8b444`、`0x8b69c` |
| 影片 | YUV420 三平面 + 步长、目标矩形、旋转 0/90/180/270、RGB565 打包模式 | `0x31ade8`、`0x31b05c`、`0x31a734` |
| 开关 | `cpu` / `gpu-raster` / `gpu-batch` / `gpu-scene`，以及 AA / 过滤 / 雾 / 画幅预设 | 本文 |

硬边界：

- host 不得改变提交集合、提交顺序、逐三角形 alpha、颜色键判定结果。
- host 不得把「更正确的」遮挡、排序或 alpha 修正当作默认行为；要改必须作为独立可选预设，并有对照证据。
- 3D 结果写回 guest 帧缓冲后，guest 的 HUD、对白、调色、受击闪白照常执行；不得在 host 侧重复实现这些层。

## 4. 专项设计

### 4.1 场景提交与可见性

现状：两级筛选——BSP 单元 + 实体法线点积（`0x51580`）、角色额外做 bbox 线段遮挡（`0x43dc0`）；渲染列表容量有限（`0x6fd70`）；深度键排序决定提交顺序，且存在一个「按深度降序」的特例分支（`0x1cdc==8 && +0x554==0x13`）。`[静态]`

设计：

- 保留 guest 的可见性与排序结果，host 只负责把「已经决定要画的东西」画对。渲染列表溢出（容量不足时静默丢弃）同样是可观察行为，不能靠「反正 GPU 能画」补回。
- 特例分支的观感差异必须实测：同一场景若在两种顺序下用同一深度缓冲得到相同结果，说明该分支只影响透明层；若不同，则 C 阶段必须保留双路径，不能合并。
- GPU 深度测试**不能**替代实体 bbox 遮挡：后者会整块隐藏实体，前者只在像素级遮挡。若将来要用 GPU 遮挡剔除，必须逐场景对照确认可见集合一致。

`[待定]` 渲染列表容量与实体数的实际上界、特例分支的实际影响面。

验收：同一相机姿态下，host 提交的三角形数量、顺序、模式分布与 guest 记录逐条相等（转储比对，不靠截图）。

### 4.2 顶点与材质

现状：两级几何——多边形对象（顶点 3×int16，`0x89e94`）与运行时 0x58 三角形记录；模型文件头 0x44 字节、记录 0x24 字节，贴图名追加 `sbm`（`0x43040`）；贴图为 4 字节 BGR 调色板 + 索引像素，解码成 RGB565 并翻转行（`0x6d1b4`）；逐面颜色经 `0x53160 NormalizeColorTriples` 归一化，`0x8a25c SetPolygonColor` 写入三色。`[静态]`

设计：

- 顶点数据以「不改变数值」为原则：16.16 屏幕坐标、深度索引、UV 按原值进入 GPU；A 阶段直接把屏幕空间坐标送顶点着色器做单位变换，避免引入第一处数值差。
- 调色板位图在 host 侧一次性解码为 RGBA8（或 RGB565 + 1 位 alpha），缓存键为「资源名 + 调色板内容」；不得因为「看起来是同一张图」而复用不同调色板的结果。
- 逐面/逐顶点颜色走纹理乘色或顶点色，保持 `0..1` 归一化后的相对关系；不做色调映射、不做伽马修正（原版是 565 直出）。
- 双纹理模式（`+0x48==5`）的混合方程 `[待定]`：需在固定镜头下取同一像素的两张源纹理值与结果值反推，先按「第二纹理调制第一纹理」实现并保留可切换公式。

`[待定]` 0x58 记录中除屏幕 xy、深度索引、模式、标志、UV 之外的字段归属；实现前用固定帧转储确认。

验收：关闭 AA 与过滤（最近邻）时，A 阶段输出的几何边缘与 guest 逐像素一致；材质平均色差在 §6.3 容差内。

### 4.3 深度

现状：32 位整数深度键，逐像素 `existing < new` 才写，越大越近；遮罩层另有独立键缓冲；合成时用 `key + 50000` 与不透明层深度比较。`[静态]`

设计：

- 忠实模式使用整数深度（`R32_UINT` 或等价）与 `GREATER` 比较，保持「越大越近」与 `50000` 偏置；不要用浮点 `1/w` 重算，那会整体改变 z 分布和共面判定。
- 增强模式可把深度重映射到浮点以获得更好的远近精度，但必须单独对照，且共面几何（贴地薄片、墙面装饰）的胜负不能翻转。
- 深度精度问题在低模小场景里主要体现为共面闪烁，不是远处精度不足；因此优先保证「同深度比较规则一致」，而不是扩展范围。

`[待定]` `50000` 的量纲（是否有对应的世界单位），以及 `+0x3c` 键的生成公式。

验收：跨越遮挡（相机前后移动经过柱子/墙角）时，遮挡翻转的帧号与像素边界与 guest 一致。

### 4.4 透明与镂空

现状：模式 6 用颜色键 `0xF81F` 逐像素丢弃，并写一个**逐三角形常量** alpha 到遮罩缓冲；合成按 `alpha/256` 线性插值；2D 侧另有调色板 `0xF81F` 透明与 `0..0x100` 逐像素 alpha。`[静态]`

设计：

- 镂空与半透明是两条机制：颜色键决定「这个像素是否属于面片」，alpha 决定「合成权重」。二者不可合并为纹理 alpha 通道后再乘一次。
- GPU 实现：模式 6 用片元丢弃（`discard`）复现颜色键，输出到遮罩层目标并写常量 alpha；不要改用混合方程近似，因为原版是「先落到层，再整层带深度门限合成」，与直接混合的顺序语义不同。
- 逐对象 `+0x172` 的 `0x40`（常规）与 `0x80`（受击闪白时）与 alpha 的关系 `[待定]`；在确认前不得把它当成额外透明度叠加。
- 2D 侧保持原样（§4.10），不把 HUD 的透明键换成 GPU alpha 测试。

验收：贴图边缘一像素带内的透明判定逐像素一致；角色与背景交叠处无色边、无黑边。

### 4.5 宽屏与画幅

现状：原生画布 176×208（竖向，宽高比 11:13），投影尺度由 `min(w,h)` 决定且两轴相同，远裁剪 2000；HUD 坐标部分按屏幕尺寸比例、部分固定偏移；影片素材只有 176×208 与 240×320 两套。`[静态]` 宿主窗口当前固定 176×208 并整帧上传（`tools/window_gc.h`）。`[运行]`

这是本设计最容易做错的一节：竖向原生画幅在 16:9 窗口里若按「填满宽度」处理，等于把画面放大到只剩中间一条，或者拉伸。因此必须先定策略再写代码。

| 方案 | 做法 | 优点 | 风险 |
| --- | --- | --- | --- |
| W1 画幅锁定（推荐默认） | 3D 目标固定 176:208，等比缩放到窗口内，四周留黑；HUD/对白锚定在内容矩形 | 零镜头风险、零资产风险、与影片天然一致 | 宽屏两侧有黑边 |
| W2 横向扩展 FOV | 保持竖向构图，X 轴单独缩放以增加水平视野 | 视觉上更像「宽屏游戏」 | 会露出未制作区域；镜头构图改变；与「保持原镜头语义」冲突 |
| W3 加宽 HUD/背景 | 3D 仍 W1，仅菜单/对白底板延伸到内容矩形外 | 宽屏观感更完整 | 需逐界面确认不留空、不遮画面 |

建议：默认 W1，可选 W3；W2 只作为实验开关，且必须逐镜头人工确认，不作为验收路径。理由：投影是单一尺度（`min(w,h)`），横向扩展必然改变水平视野；原版没有对应素材与镜头数据，属于「伪造新场景」的边界。

具体约束：

- 缩放优先整数倍 + 最近邻（保持像素风与原纹理观感）；非整数倍时用高质量缩放并可切换。
- HUD、对白框、菜单锚定到**内容矩形**，不是窗口；用安全边距（例如内容矩形的 2% 或 2 像素，取大者）。
- 过场与影片保持素材比例，必要时留黑边；不得裁切、不得拉伸、不得改变播放时长与音画同步。
- 交互与碰撞不受影响：命中点、拾取距离、鼠标坐标都要先映射回内容矩形再进 guest。

`[待定]` 竖向画幅在超宽窗口下的最小可读尺寸；HUD 固定偏移路径在 240×320 与 176×208 之外的屏幕尺寸下的表现（需实测，不可外推）。

验收：在 16:9、16:10、4:3、21:9 与 176:208 五种窗口下，场景构图中心、地平线、角色屏幕位置一致（相对内容矩形）；HUD 元素不贴边、不重叠、不遮关键画面；影片留边对称。

### 4.6 抗锯齿

现状：1 采样/像素，无 AA、无 mipmap，最近邻采样。`[静态]`

设计：

- 几何边缘优先用 MSAA（4×）并在最终呈现时解析；A/B 阶段的可对照性最好。
- 颜色键镂空边（树木、栅栏、贴图剪纸）用 `discard` 时 MSAA 对该边缘无效；要获得边缘 AA，需要把 1 位颜色键转成 alpha-to-coverage。这会改变边缘观感，属于增强项，必须单独开关并单独对照。
- 不建议 TAA：低分辨率素材 + 逐帧变化的抖动会糊掉像素风贴图与文字；若将来要做，必须先解决文字与 HUD 的排除。
- 后处理式 AA（FXAA/SMAA）可作为「不想动几何」的折中，但会模糊 1 像素宽的镂空细节，默认关闭。
- 2D/HUD/文字层不参与 AA；文字必须在原生分辨率下以最近邻呈现，否则可读性下降。

`[待定]` 具体方案与采样数由实测的「边缘改善 vs 文字/镂空损失」决定；默认建议 MSAA 4× + 2D 层不参与。

验收：关闭 AA 时与基线逐像素一致；开启后差异集中在几何边缘 1–2 像素带内，文字区域差异为 0，镂空边缘不出现缺口或加粗。

### 4.7 纹理过滤与 mipmap

现状：调色板位图，16.16 UV，`>>16` 最近邻；原生画布 176×208，素材与屏幕基本 1:1。`[静态]`

关键判断：在 PC 上常见窗口远大于 176×208，绝大多数表面处于**放大**采样，mipmap 与各向异性过滤对画质几乎没有贡献；真正决定观感的是放大过滤（最近邻 vs 双线性）与内部渲染分辨率。因此：

- 默认（原版观感）：最近邻放大，关闭 mipmap。
- 可选（柔和）：双线性放大 + mipmap + 各向异性，仅用于 3D 表面；HUD/文字/影片保持最近邻。
- 若开启更高内部渲染分辨率，纹理才可能出现缩小采样，此时才需要 mipmap；生成 mipmap 必须 alpha 感知——颜色键 `0xF81F` 在降采样时会被平均成非键颜色，产生紫边。做法：先由颜色键生成 1 位 alpha，再按 alpha 加权下采样，最后重新应用键/alpha。
- 不改变纹理尺寸与内容：过滤只影响采样，不允许重绘、放大或锐化素材。

`[待定]` 放大过滤的默认值需与用户确认观感；建议默认最近邻（与像素风一致），并在设置里提供「柔和」预设。

验收：最近邻模式下与基线逐像素一致；柔和模式下不出现紫边、不出现 1 像素亮线；文字保持锐利。

### 4.8 三档雾

先说清楚证据边界：**静态证据里没有独立的距离雾函数**。已确认的只有：清屏值为 0（黑）、远裁剪 2000、逐面颜色/明暗、遮罩层合成、全屏调色。因此「原版风味」这一档首先是一个**测量任务**，不是一个已知参数。

三种可能，必须用运行对照判定：

1. 原版无雾，远景物靠「黑底 + 暗贴图 + 2000 远裁剪」自然消失；
2. 原版有烘焙在逐面颜色里的距离衰减（`NormalizeColorTriples` + 逐面三色）；
3. 原版用遮罩层做远景压暗（模式 6 的常量 alpha 大面积覆盖）。

设计（参数化，不锁死数值）：

| 档位 | 定义 | 参数来源 |
| --- | --- | --- |
| 原版风味 | 复现测量结果；若测量为「无雾」，则密度 0 且保持原远裁剪 2000 | 测量/逆向 |
| 更沉浸 | 线性或 exp2 距离雾，起雾距离与远裁剪解耦；颜色取自该图背景/平均暗色 | 预设，可按图微调 |
| 关闭 | 密度 0，允许把远裁剪推远到覆盖该图全部几何 | 逐图实测 |

约束：

- 雾只影响 3D 几何，不影响 HUD、对白、影片。
- 雾不得作为隐藏几何的手段而不做验证：远裁剪推远后若露出未制作区域，用地图边界、天空/背景层或保守裁剪处理，不伪造新资产。
- 雾参数不得写入地图文件或存档；属于渲染设置。
- 颜色运算空间要与基线一致（565 直出），否则同一密度在两档之间会出现色带差异。

`[待定]` 原版距离衰减是否存在、公式与单位；2 与 3 的判定需要固定相机在同一走廊/石阶上做「距离-亮度」采样。

验收：原版风味档与基线逐像素一致（或差异仅在已知容差内）；更沉浸档在 3 个距离点上单调变暗且不产生色偏；关闭档不改变碰撞、交互距离与脚本结果，且不出现明显「空气墙」边界。

### 4.9 保留低模与资产约束

- 不细分、不置换、不重算顶点法线、不做平滑组重排；轮廓必须与原版一致（低模的棱角是风格的一部分）。
- 不上调贴图分辨率、不做 AI 放大、不重绘调色板；调色板解码只做格式转换。
- 不引入 PBR、屏幕空间反射、体积光等与资产不匹配的效果；光照仍以逐面颜色/明暗与原始贴图为主。
- 允许的增强仅限本文列出的：AA、过滤（可选）、雾（预设）、内部分辨率、画幅策略。
- 任何「看起来更好」但改变轮廓、贴图内容或明暗关系的改动，都属于资产/玩法改动，不在本设计范围。

验收：同一相机姿态下，物体轮廓面积比与基线差异 < 0.5%；贴图平均色与方差在容差内；不存在新出现的边缘细节。

### 4.10 HUD、对白与菜单层

现状：索引位图 blit + 调色板透明键 + 逐像素 alpha + 改色；坐标由屏幕尺寸比例与固定偏移混合决定；字形来自 SBM 位图，宿主侧用 FreeType 渲染系统文字（`tools/window_gc.h`）。`[静态]` `[运行]`

设计（分两步，不要一次做完）：

1. 保留 guest 2D：3D 结果写回 guest 帧缓冲后，guest 的 HUD/对白/菜单/调色照常执行，host 只上传最终画布。这是 P2–P4 的默认形态，零风险。
2. 2D 上移（可选）：在 host 侧建 2D 层，需要 guest 的 blit 调用同时产生覆盖率，否则无法与 3D 层正确合成（因为 guest 清屏是黑色）。在覆盖率机制可靠之前不要做。

无论哪一步：

- 2D 层以原生分辨率渲染，最近邻，1:1 像素对齐；非整数缩放会让 1 像素边框与字形笔画变粗或消失。
- 文字不参与 AA、不参与雾、不参与调色（除原版自身的全屏调色）。
- 对白框、菜单底板随内容矩形锚定；不随窗口宽度拉伸。
- HUD 元素之间的相对位置必须与基线一致（同一内容矩形下逐元素比较包围盒）。

`[待定]` `0x69108` 中比例系数与固定偏移的混合规则在 176×208 之外的行为；必须在目标窗口尺寸下实测，不能按公式外推。

验收：五种窗口尺寸下 HUD 元素包围盒相对内容矩形的偏差 ≤ 1 像素；文字无模糊、无重影、无截断。

### 4.11 影片层

现状：guest 解码 MPEG-4/AVI，YUV420 → RGB565（BT.601 有限范围，`0x31ac80` 系数表），支持 0/90/180/270 旋转，分辨率按屏宽选择 176×208 / 240×320。`[静态]`

设计：

- 影片作为独立层，按素材原始比例适配内容矩形，必要时留黑边；不拉伸、不裁切、不改变时长。
- 第一阶段保留 guest 解码与 blit（现状），host 只负责呈现；第二阶段可把 YUV 平面直接作为纹理上传，在 GPU 做 YUV→RGB，但色彩矩阵、范围（limited/full）与 565 打包必须与 `0x31ac80` 一致，否则肤色会偏。
- 旋转只在素材元数据要求时使用；PC 上不因窗口方向改变旋转。
- 影片期间不叠加雾、AA、调色（除原版自身的淡入淡出）。

`[待定]` 影片是否与原版一样在 176×208 之外留边、以及是否参与全屏调色（需逐段对照）。

验收：与基线逐帧比较关键帧（首帧、字幕帧、转场帧）的色彩直方图；留边对称；无拉伸导致的圆形变椭圆。

### 4.12 CPU 后处理迁移

现状清单（全部在 guest 侧，逐像素）：

| 后处理 | 位置 | 作用域 |
| --- | --- | --- |
| 遮罩层合成 | `0x62f08` | 全帧，带深度门限与 565 整数插值 |
| 受击全屏提亮 | `0x68ea0` 内联 | 全帧，对 R/G 分量加法 |
| 状态 `0x1a` 调色/淡出 | `0x68ea0` 内联 | 全帧，逐像素通道缩放 |
| 2D alpha 混合 | `0x8b444`、`0x8b844` | 矩形区域 |
| 影片 YUV→RGB | `0x31ade8`、`0x31b05c` | 全帧 |

迁移策略（按收益/风险排序，逐项独立，不做大爆炸）：

1. **不迁移**：受击提亮与状态调色保留在 guest。它们是全帧整数运算、成本低、语义与游戏状态强耦合，迁移收益小、回归风险大。
2. **随 3D 一起迁移**：遮罩层合成。它是 3D 管线的一部分，C 阶段必须在 GPU 内完成（否则要先回读遮罩层再合成，反而更慢）。忠实实现要点：565 目标、按通道整数插值、`key + 50000` 门限、幂等分支。
3. **可选迁移**：影片 YUV 转换（解码仍留在 guest）。收益是少一次 CPU 全帧写，风险是色彩矩阵不一致。
4. **最后考虑**：2D alpha 混合。需要覆盖率/分层机制，收益最低，建议长期保留。

精度取舍：GPU 在 565 目标上的混合内部精度可能高于原版整数运算，逐像素会有 ±1 个色阶差。两种处理：

- 接受容差（推荐）：在对照报告里明确「565 混合 ±1」属于已知差异；
- 逐位一致：把合成写成整数着色器，输出到 `R16_UINT` 再转 565；成本更高，仅在出现可见色带时启用。

回读成本：3D 结果写回 guest 帧缓冲为每帧 73 KB，可忽略；不要为了「省一次拷贝」而把 2D 层也搬上 GPU——那会引入覆盖率与顺序的全新问题。

## 5. 分阶段迁移

| 阶段 | 内容 | 出口条件 | 回退 |
| --- | --- | --- | --- |
| P0 基线 | 现状：guest 全 CPU，宿主整帧上传 | 序章可玩、帧哈希稳定、可重复采集 | — |
| P1 呈现层 | 画幅策略（W1/W3）、整数缩放、最近邻、窗口模式；3D 仍全 CPU | 五种窗口下构图与 HUD 锚定通过；像素内容不变 | 关闭缩放 |
| P2 GPU 光栅器（A） | 屏幕空间三角形、采样、颜色键、深度、遮罩层；guest 继续变换/投影/排序 | 关闭 AA/过滤时与 P1 逐像素一致或仅在已知容差内；顺序敏感场景一致 | `--renderer=cpu` |
| P3 GPU 变换与裁剪（B） | 相机空间批次上行，GPU 做近裁剪、透视除法、光栅 | 几何偏差在容差内；遮挡翻转帧号一致；共面无翻转 | 退回 A |
| P4 GPU 场景管线（C） | 静态网格 VB/IB、逐对象矩阵、两层目标 + 合成着色器；guest 3D 走跳过分支 | 序章与第一章 A/B 通过；宽屏、AA、过滤、三档雾各自单独验收 | 退回 B |
| P5 2D/影片/后处理（可选） | 影片 YUV 着色器、2D 层化（需覆盖率） | 每项单独 A/B；文字与对白零回归 | 逐项关闭 |

每个阶段的共同要求：新增开关，不删除 CPU 路径；一次只启用一个变量（AA、过滤、雾、画幅分开对照），不合并验收。

## 6. 逐项画面对照方法

### 6.1 采集条件

- 同一构建、同一安装盘副本、同一起始存档槽；每轮用新的盘副本避免存档漂移。
- 固定输入脚本（按键序列 + 帧号），关闭窗口缩放与系统缩放，固定窗口尺寸，关闭 vsync 影响（或固定刷新率）。
- 每帧导出：176×208 RGB565 帧缓冲、`guest frame` 的 FNV-1a 哈希（`tools/window_gc.h` 已有）、以及（P2 起）深度/键/alpha 三缓冲转储、相机与对象矩阵。
- 同一 P0 基线至少采两次，确认哈希可重复；不可重复的项目不进入像素判据，只做人工观察。

### 6.2 对照项清单

| 项 | 基线 | 变体 | 判据 | 失败处置 |
| --- | --- | --- | --- | --- |
| 场景提交集合 | P0 转储 | 各阶段转储 | 三角形数、模式分布、顺序逐条相等 | 定位到可见性/列表/排序哪一级 |
| 深度与遮挡 | 柱子/墙角前后移动 | 同 | 遮挡翻转帧号与边界一致 | 检查深度方向、偏置、比较函数 |
| 不透明贴图 | 静态墙面 | 同 | 平均色差、边缘 1 像素带差异 | 检查 UV 定点、最近邻、调色板解码 |
| 透明/镂空 | 树木、栅栏、角色边缘 | 同 | 透明判定逐像素一致；无色边 | 检查颜色键、discard、层合成顺序 |
| 双纹理 | 水面/装饰面 | 同 | 同像素两源值与结果反推公式 | 保留可切换公式，继续测量 |
| 逐三角形 alpha | 半透明遮挡物 | 同 | 合成权重一致（±1 色阶） | 检查常量来源 `+0x172` |
| 受击闪白 | 被打一次 | 同 | 提亮幅度与持续帧数一致 | 该项应留在 guest，若不一致说明顺序错 |
| 全屏调色 | 状态 `0x1a` 转场 | 同 | 逐像素通道关系一致 | 同上 |
| HUD 锚定 | 五种窗口 | 同 | 包围盒偏差 ≤ 1 像素 | 检查内容矩形与固定偏移路径 |
| 文字 | 对白、菜单 | 同 | 文字区域差异为 0 | 关闭该层 AA/过滤 |
| 影片 | 开局影片关键帧 | 同 | 直方图一致、留边对称、圆不变椭圆 | 检查缩放矩阵与色彩范围 |
| AA | 关闭 vs 开启 | 同 | 差异仅在边缘 1–2 像素带；文字区 0 | 调整方案或关闭 |
| 过滤 | 最近邻 vs 柔和 | 同 | 无紫边、无亮线、文字锐利 | 检查 mipmap 的 alpha 感知 |
| 雾：原版风味 | 测量结果 | 同 | 与基线一致或差异在容差内 | 先完成测量，不先写实现 |
| 雾：更沉浸 | — | 3 个距离点 | 单调变暗、无色偏 | 调整起雾距离/指数 |
| 雾：关闭 | — | 远裁剪推远 | 不露未制作区域；碰撞/交互不变 | 加边界/背景层或保守裁剪 |
| 宽屏构图 | 176:208 | 五种窗口 | 构图中心、地平线、角色位置相对内容矩形一致 | 回到 W1 |
| 低模轮廓 | 角色、道具剪影 | 同 | 轮廓面积比差 < 0.5% | 检查是否误开细分/平滑 |

### 6.3 容差

- 几何：边缘像素允许 1 像素偏移（来自定点/浮点舍入）；轮廓面积比 < 0.5%。
- 颜色：不透明区域逐像素差 ≤ 1 个色阶（5/6/5 各自）；平均色差与方差在 2% 内。
- 混合：透明区域 ≤ 1 个色阶，且不得出现沿边缘的连续差异带。
- 文字与 HUD：0 差异（除缩放策略本身）。
- 影片：直方图相似度为主，单帧逐像素不作为硬判据（解码器实现差异）。

### 6.4 不能只看截图的项

- 提交顺序与特例分支（`0x1cdc==8 && +0x554==0x13`）：必须转储顺序，静态截图可能完全一样。
- 渲染列表溢出：必须在实体密集场景观察是否出现「少画」。
- 深度共面：需要相机缓慢移动的连续帧，静态帧看不出来。
- 帧内后处理顺序：受击闪白在合成之前、HUD 之前，顺序错时单帧可能仍然「像」。
- 影片音画同步：需要连续播放，不看单帧。

## 7. 风险与未验证项

| 编号 | 内容 | 影响 | 验证方式 |
| --- | --- | --- | --- |
| R1 | 间接调用实参在反编译中丢失，四缓冲归属为推断 | 层合成实现可能整体错位 | 固定帧转储五个缓冲，逐一比对内容特征 |
| R2 | 深度键量纲与 `50000` 偏置含义未证 | 遮罩层与不透明层的胜负可能翻转 | 构造共面/近共面对照 |
| R3 | `+0x172`（`0x40`/`0x80`）与 alpha 的关系未证 | 角色透明度可能错误 | 受击前后逐像素比较 |
| R4 | 透视校正表索引 `depth>>9` 的钳位与精度未证 | 斜视大面片纹理可能拉扯 | 贴地长面片多角度对照 |
| R5 | UV 16.16 溢出/回绕规则未证 | 大面片边缘可能出现纹理跳变 | 全图扫描 + 转储 UV |
| R6 | 双纹理混合方程未证 | 水面/装饰面观感错误 | 反推公式，保留切换 |
| R7 | 原版是否有距离雾未知 | 「原版风味」档无法先实现 | 距离-亮度采样，见 §4.8 |
| R8 | 投影单尺度、依赖 `min(w,h)` | 直接改画幅必然拉伸 | 锁定画幅或显式 X 缩放 |
| R9 | HUD 比例与固定偏移混合 | 新窗口尺寸下 HUD 可能错位 | 逐尺寸实测包围盒 |
| R10 | 影片仅两套素材分辨率 | 宽屏拉伸风险 | 按素材比例适配 |
| R11 | `texture\scene\` 缺贴图 | 基线本身不完整，差异无法归因 | 对照报告标注已知差异，不自动回退 |
| R12 | GPU 565 混合精度高于整数实现 | 逐像素 ±1 色阶 | 容差或整数着色器 |
| R13 | MSAA 对颜色键边缘无效 | 镂空边缘无 AA | alpha-to-coverage 或接受 |
| R14 | mipmap 破坏颜色键 | 紫边 | alpha 感知下采样 |
| R15 | 回读/上传与 guest 帧序耦合 | 撕裂或一帧延迟 | 双缓冲，guest 状态不变 |
| R16 | 渲染列表容量上界未知 | 密集场景可能少画 | 密集场景转储计数 |

## 8. 渲染侧验收清单

1. P0 基线两次采集哈希一致；对照矩阵、窗口尺寸、输入脚本记录完整。
2. 关闭所有增强时，P2/P3/P4 与 P0 在序章逐像素一致或差异全部落在 §6.3 容差内，且每处差异都有归因。
3. 顺序敏感项（遮挡翻转、透明交叠、共面）逐帧一致；特例提交分支保留且已实测其影响。
4. 五种窗口尺寸下构图中心、地平线、角色位置、HUD 包围盒符合 §4.5/§4.10；影片留边对称、无拉伸。
5. AA、过滤、三档雾每项单独开关、单独对照；文字区差异为 0；镂空边缘无缺口。
6. 雾的任何档位都不改变碰撞、交互距离、AI 与脚本结果；关闭档不暴露未制作区域。
7. 低模轮廓、贴图内容、调色板、UV 未被修改；无新增多边形与重绘素材。
8. 第一章与序章分别报告；不用序章结果代替第一章。
9. 每个阶段都有可用的回退开关，CPU 渲染路径可随时切回并产生与 P0 一致的画面。
10. 未验证项（§7）在文档中保持 `[待定]` 状态，不以「看起来一样」升级为事实。
